# Frames and templates

Architecture notes, moved out of CLAUDE.md on 7 October 2026 so they load only when needed. Sections are in build order and keep the version that introduced them; later sections can override earlier ones. A quoted section name ("Frame multi-select") may live in another file: see `docs/architecture/README.md`.

## Frames, protocol v9 (slice frames)
- `PROTOCOL_VERSION = 9`. A frame is `{ id, x, y, w, h, title, color, rev, authorId }` (`frameSchema`). Constants in shared: `MAX_FRAMES_PER_ROOM` 30, `MAX_FRAME_TITLE` 60, `FRAME_DEFAULT_W/H` 640×400, `FRAME_MIN_W/H` 240×160, `FRAME_MAX_W/H` 2400×1600 (tokens `--sy-frame-*`, test checks), `FRAME_COLORS` (neutral + the six note hues; keys, never CSS). `cleanFrameTitle` (one line, may be empty), `clampFrameRect`/`clampFramePosition`, and `groupOffset` (moved to shared; `canvas/arrange.ts` re-exports it) for the carry clamp. v8 pages get `version_mismatch`.
- Client (strict): `frameAdd { clientRef, x, y, color, title }`, `frameEdit { id, title?, color? }` (at least one), `frameMove { id, x, y, final, noteIds? }` (unique, at most `MAX_BATCH_ENTRIES`), `frameResize { id, x, y, w, h, final }`, `frameDelete { id }`. Server: `frameAdded` (`clientRef` only to the sender), `frameUpdated` (whole frame), `frameMoved { id, x, y, rev, final, notes? }` (the carried notes' new places in the same message: one view update), `frameResized`, `frameDeleted`; `error` may carry `frameId` (plus `noteIds` for a carried move); new code `frames_full`.
- Join sequence: the Worker sends `joined`, then `snapshot` (notes only, shape unchanged), then `framesSnapshot { frames }` (strict, at most 30) in the same handler step, so nothing can land between them (tested). The web treats the board as joined and synced after `snapshot` (notes render, the first fit runs) and applies `framesSnapshot` when it arrives (frames slot in behind; no viewport jump). Frame messages before it are applied as usual and `applyFramesSnapshot` merges by rev (a newer frame already here wins; local pending adds stay), so nothing is lost. No `framesSnapshot` (an older relay, or lost) leaves notes and no frames, with no error or retry. The notes snapshot's worst case and 400 KiB tripwire are unchanged; the frames message has its own worst-case test (15,096 bytes).
- Worker (`room.ts` `handleFrame`): last-write-wins, rev per stored change, unknown/deleted ids ignored. A final `frameMove` takes the named notes that exist, clamps one delta for frame + notes (`groupOffset`), writes the frame and every changed note in one `applyFrameMove` transaction (1 + N rows at most) and broadcasts one `frameMoved` with every carried note (changed or not). Live moves/resizes are relayed to the others via `pendingFrames` (coalesced, never stored). Carried ids on a final move spend `BATCH_LIMITS` (`entriesOf`). Delete removes only the frame.
- Stored schema `SCHEMA_VERSION = 6`: `CREATE TABLE IF NOT EXISTS frames (...)`, every column but the key with a DEFAULT; additive, notes untouched. Tested against `worker/test/fixtures/schemaV5.ts` and the exact v8 note statements on schema 6. Off-board frame rows are clamped on load. An insert counts 2 rows written (row + primary-key index).
- Web: `frames/board.ts` (pure: `BoardFrame` with `confirmed`, `clientRef`, `draft`, `dragging`/`resizing` and `isFrameHeld`; `applyFramesSnapshot` and the other `applyFrame*`, `rollbackFrame`, local `addFrameLocal(FrameDraft)` etc., `framedNotes` = notes whose centre is inside). `Board` gains `frames` and `framesRemoved`. `RoomSession`: `addFrame` (plain data, so code like templates can call it), `editFrame`, `setFrameDraft`, `startFrameDrag(id, carry)` (carries the framed notes, or none with a `NOTICES.frameTooFull` notice over the cap), `moveFrame` (group clamp, throttled), `startFrameResize`/`resizeFrame`/`setFrameSize`, `deleteFrame`; `onFrameConfirmed` renames ids.
- Canvas: frame nodes come before notes, at `FRAME_Z_INDEX` (= `-NOTE_Z_LIMIT - 1`: behind every note, above the board at `-NOTE_Z_LIMIT - 2`; z-order never touches frames). The node has `pointerEvents: "none"` and `dragHandle: ".sy-frame-handle"`: only the header and edge strips (`frames/FrameNode.tsx`) take presses, so clicks, marquees and pans start on the canvas and notes inside work as before. Alt at drag start = alone (`createDragHandlers` `startFrameDrag`/`moveFrame`). Resize handles via `NodeResizer` for the one selected frame (`.sy-frame-node .react-flow__resize-control` gets pointer events back). Phones: frames shown, not draggable, title as text.
- Selection: since v0.20.0 a frame set `uiStore.frames` beside the note set (see "Frame multi-select"); `frameSelected` is derived (the one frame selected alone, else null) and is what single-frame UI (FrameFields, resize handles, Enter to edit) reads; `frameEditRequest` focuses the header title (kept until the confirmed node has focus, since the node remounts when its id changes). Delete key and Properties delete ask first when it has a title or notes inside (`frames/label.ts`). Properties shows `frames/FrameFields.tsx` (Title draft, Colour swatches, Width/Height, author).
- Palette: a "Frames" category (`FRAME_TILES`, `surfaces: ["panel"]`, so not in the phone drawer); `PaletteActions.addFrame`, `PaletteContext.frameReason`, items may give a `dropSize`. Fit and the initial fit include frames; the minimap draws them in their border colour. Look: `frames/style.ts` maps keys to `--sy-frame-<key>-fill/-border/-header` and `--sy-frame-title` (both themes; title 4.5:1 on every header, tested).

## Frame title styling, protocol v10 (slice frame title styling)
- `PROTOCOL_VERSION = 10`. A frame adds `titleFontSize`, `titleBold`, `titleItalic`, `titleTextColor`, `titleAlign` (the note key sets). `FRAME_DEFAULTS` = m, bold, upright, auto, left (looks like v9's header). `FRAME_STYLE_FIELDS`, `FRAME_EDIT_FIELDS` (title, color + the five): all optional `frameEdit` fields, at least one. `frameAdd` carries no style. `frameSchema` stays non-strict (unknown fields stripped). v9 pages get `version_mismatch`.
- Stored schema `SCHEMA_VERSION = 7`: `V7_FRAME_COLUMNS` (each `NOT NULL DEFAULT` from `FRAME_DEFAULTS`, nothing backfilled). Tested against `worker/test/fixtures/schemaV6.ts`, including the exact v9 frame insert/update statements on schema 7. `handleFrame` frameEdit compares every `FRAME_EDIT_FIELDS` field: unchanged = no write, no broadcast.
- Web: `frames/style.ts` `frameInkToken` (auto = `--sy-frame-title`, else frame-only `--sy-frame-text-<ink>`: the note ink values in light, lighter inks in dark, 4.5:1 on every frame header tested), `frameRootStyle` (sets `--sy-frame-header-h` to `--sy-frame-header-<size>`: 44/44/48/56px, so the header and the side strips follow; the largest header + edge leaves 92px of body at `FRAME_MIN_H`), `frameHeaderStyle`, `frameTitleClasses` (bold = `font-semibold`, a little lighter than note bold; not bold = `font-normal`), `FRAME_INK_SWATCHES`. `frames/board.ts` `FrameEdit`, `frameChanges`, `editableFields`; `RoomSession.editFrame(id, FrameEdit)` sends only changed fields (and all of them once an add is confirmed). `notes/StyleFields.tsx` `TextStyleSection` is the generic Title/Body text section; `PartTextSection` (notes) and `FrameFields` (frames) both use it.
- framesSnapshot worst case 18,306 bytes; test cap 20 KiB, and the test also fails past 90% of it (new per-frame field = decision first; docs/LIMITS.md).

## Templates (slice templates)
- Web only, no protocol change. `web/src/templates/registry.ts` `TEMPLATES` (plain data: per frame title, colour key, x/y/w/h in board units from 0,0, title style keys); a new template is one entry. Tested: titles clean and within the cap, keys valid, sizes within frame limits, on the board, no overlaps, within the room cap. `templates/place.ts` (pure): `templateBounds`, `templateOrigin` (click: centred on the viewport centre), `clampTemplateOrigin` (drop: the palette's dropAt gives the box's top-left), `placeTemplate`.
- Palette: "Templates" category (`TEMPLATE_TILES`, `surfaces: ["panel"]`), preview kind `template` (frames in miniature, `frameSwatchStyle` tokens), `dropSize` = the template's bounds, `PaletteActions.applyTemplate`, `PaletteContext.templateReason` (`templateToolReason`: disconnected, or one being applied).
- `RoomSession.applyTemplate(plans)`: refuses (nothing sent) when not live, while another runs, or with too few free frame slots (`NOTICES.templateNoRoom(needs, free)`). Since v0.11 it sends every frame with its size, title and title style through `addItems` (one `itemsAdd` per template today): no paced resize/style steps, no settling. Any refused item, or a disconnect, ends it as `partial` (`NOTICES.templatePartial`; frames made stay, queued messages of the run are dropped, nothing retried). `RoomView.template` (`TemplateRun`: seq, state, frameIds); `RoomBoard` fits to the frames and selects the first when a run is `done`.

## More built-in templates (v0.29.0)
- Web only: data plus a palette registry change; no protocol, stored-schema or relay change. Fifteen templates (four from v0.10.0, eleven new). Each `Template` has a `group` (`TemplateGroup`, from `TEMPLATE_GROUPS`: Retros, Planning and facilitation, Architecture and analysis, each with its palette `categoryId`); `TEMPLATES` is kept group by group in that order (Sprint planning now comes before 2x2 Impact and Effort). Layout helpers in `registry.ts`: `columns` (3 or 4 columns, 480 wide, 40 apart), `quadrants` (2 x 2, 600 x 440), `row` (column-wide frames 440 tall, for Starfish's 3 + 2 and Migration strategy's 3 x 2), `THREE_W` (the banner over three columns: Sprint goal, Sailboat's Goal). Same conventions as before: `HEADING` titles (`BANNER` for the wide goal), one colour per frame within a template.
- 2 x 2 titles carry their axes: SWOT (rows internal / external, columns helpful / harmful), TIME (business value up, technical fit to the right: Migrate top left, Invest top right, Eliminate bottom left, Tolerate bottom right). Longest title 40 characters (Quick wins), under `MAX_FRAME_TITLE` 60, which is unchanged.
- Palette: one category per group (`templates-retros`, `-planning`, `-architecture`, orders 3, 3.1, 3.2, `surfaces: ["panel"]`) built in `PALETTE_CATEGORIES` from `TEMPLATE_GROUPS` with a local `templateTile`; the old single "templates" category and `TEMPLATE_TILES` are gone. So each group heading is the existing category `<h3>` labelling its `<section>` (no tab stop, token colours), and search hiding an empty group is `paletteSections`' existing rule; `Palette.tsx` and `SidePanel` are unchanged. Chosen over sub-headings inside one Templates category, which would have meant changing the `Sections` component every category shares. The collapsed strip shows the groups with its usual separators.
- Capacity: largest template 6 frames (Migration strategy), 1,355 bytes as one `itemsAdd` at the board's far corner (33% of 4 KiB); every template is one message (tested). Frame cap 30 a room; the free-slots check and `NOTICES.templateNoRoom` are unchanged. Templates apply during a silent round (frames only; the relay adds frames in `itemsAdd` while a round runs). Tests: `web/test/templates.test.ts` (groups, titles, layouts, clamping at every corner, bytes, slots, silent round, search across groups), `web/test/palette.test.ts`, `web/test/roomsUi.test.tsx`.

## Frame multi-select (v0.20.0)
- Web only: no protocol or stored-schema change (reuses frameMove/frameResize/frameEdit/frameDelete, noteBatch, itemsAdd). md and up only; phones unchanged (frames shown, not selectable).
- Store: `uiStore.frames` (insertion-ordered set, like `selection`) with `toggleFrame`, `setSelections(notes, frames)`, `selectAll(noteIds, frameIds)`, `pruneFrame`/`renameFrame` on the set; `frameSelected` is derived by every update (`both()`), the frame selected alone. `select`/`selectFrame` select one item and clear the other set; `toggle`/`toggleFrame` keep it.
- Pure rules in `canvas/frameSelect.ts`: `marqueeFrames` (full enclosure, edges count; notes stay partial overlap), `selectionLabel`/`itemsLabel` ("3 notes, 2 frames selected"), `deleteCounts` + `confirmDeleteSelection` (one confirm: counts plus unselected notes inside the frames that stay), `carryPlan` (frames in selection order carry their framed notes, each note once to the first frame; a frame over `MAX_BATCH_ENTRIES` carries none and is reported in `alone`; no carry with Alt; `loose` = selected notes nobody carries), `arrangeReason`/`ARRANGE_HINTS` (mixed = off with the reason as visible text `data-arrange-reason`).
- Page: FrameNode Shift/Ctrl/Cmd-click toggles (`FrameActions.toggleFrame`, `noteClick`), a plain click selects just it; selected frames get `.sy-selected` and, with 2+ items, the `.sy-select-badge`; the dashed box covers notes and frames. `useMarquee` takes `frames`. Ctrl+A selects all notes and frames. `deleteKeyTarget` returns `"selection"` for 2+ frames or frames with notes (state `frames`). Properties: `group` (frames with anything else) shows `selectionLabel` and a bin `Delete N notes and M frames`; frames only (2+): `frames/FramesFields.tsx` (Colour and Title text via `RoomSession.editFrames`, Title Mixed/disabled, Width/Height disabled with `FRAMES_TEXT.size`); with notes: `GroupFields` text. Single note / single frame unchanged.
- Group move: `createDragHandlers` asks `selectionDragFor(id, type)` first (grabbed item in a selection with frames and 2+ items) and then drives `startSelectionDrag(carry)` / `moveSelection(dx, dy, final)` with the grabbed item's offset. Session: `startSelectionDrag(frameIds, noteIds, carry)` (confirmed, not held; `NOTICES.frameTooFull` if any frame is `alone`), `moveSelection` (one `groupOffset` over every frame and note; returns the applied delta). Live: `SELECTION_MOVE_INTERVAL_MS` 100, `SELECTION_LIVE_MESSAGES` 2 per tick (loose batch first, then frames in turn) = 20 msgs/s. Final: one `frameMove` per frame with its `noteIds` + loose notes as final batches, one history step (`recordRects`, coalesce key `move:<ids>`). Arrow keys: NoteCard's `moveSelection` and the window handler (frames selected, focus on the board) use `nudgeSelection` (one selection drag per burst, committed `KEY_COMMIT_MS` after the last press). Worst case in docs/LIMITS.md.
- Delete: `RoomSession.deleteSelection(noteIds, frameIds)` = Clear board's run (`startRemoval`, `ClearRun.kind` "clear" | "delete"): notes in batches, then one frameDelete per `CLEAR_FRAME_STEP_MS`; `RoomView.deleting` while it runs (Clear board hint `CLEAR_HINTS.deleting`, End session blocked); report via `removalReportFor("delete", ...)` ("Deleted 3 notes and 2 frames."); one history step "Delete". `BoardCanvas.deleteSelectionAsking` is the one path (key, bar, Properties).
- Arrange: `arrange.ts` functions take a `Clamp` (default `clampNoteRect`; frames `clampFrameRect`). BoardBar takes `frames`, `framesHeld`, `framesUnsaved`, `applyFrames`; frames only = arrange on frames, mixed = off. `RoomSession.applyFrameRects(rects)`: position changes carry framed notes (frameMove with noteIds, delta clamped with `groupOffset` like the relay; over the cap alone + notice), size changes are `frameResize` alone; one history step "Arrange".
- Frame edits: `RoomSession.editFrames(ids, change)` (no title): local at once, one `frameEdit` per changed frame queued and paced (`frameEditQueue`, `CLEAR_FRAME_STEP_MS`; dropped on disconnect), one history step "Edit frames".
- Duplicate: `duplicateSelectionInputs(notes, frames)` (one `groupOffset` for all; frames alone first, then notes in stacking order); `RoomSession.duplicateSelection(noteIds, frameIds)` returns local ids by kind (the copies become the selection); `duplicateDisabledReason` takes `frames` (`DUPLICATE_HINTS.framesFullMany`). Order acts on selected notes; frames only = `ORDER_HINTS.frame`.
- All new session commands refuse (nothing sent) while disconnected and for a guest on a locked board (`lockedOut`); the UI shows the lock's reason. Tests: `test/frameSelect.test.ts`, `test/frameSelectUi.test.tsx`, `test/frameSelectMove.test.ts`, `test/frameSelectArrange.test.ts`; `inRoom` takes `frames`, `frameAt` makes one.

## Board size (v0.23.0)
- Frames on the 6400 x 4000 board (protocol v16, see canvas.md "Board size, protocol v16"): limits unchanged (240 x 160 to 2400 x 1600, 30 a room). The worst-case framesSnapshot is 18,366 bytes (positions now 4 digits), 66 bytes under its 90% tripwire: a new per-frame field needs a decision first.
