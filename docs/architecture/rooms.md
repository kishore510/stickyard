## Rooms and protocol v2 (slice 1)
- `PROTOCOL_VERSION = 2`. Client: `hello`, `join { name }`, `say { text }`. Server: `welcome`, `error`, `joined`, `participant_joined`, `participant_left`, `echo`. `/ws` without a code only answers a v1 hello with `version_mismatch` (compatibility for old pages); keep that until a later protocol bump replaces it.
- Room code `<id>.<sig>` (see `worker/src/roomCode.ts`). The Worker verifies it, in constant time, BEFORE touching any Durable Object; invalid codes all get the same 404. Rooms are addressed by `id`.
- All secret comparisons go through `safeEqual` (`worker/src/crypto.ts`: SHA-256 both sides, `timingSafeEqual`).
- Secrets `CREATE_PASSCODE`, `ROOM_SIGNING_KEY` (pushed from GitHub secrets by the deploy job) and the kill switch `CREATION_ENABLED` (set by the "Room creation switch" workflow). Missing secrets fail closed.
- Abuse limits live in `worker/src/limits.ts`; participant and text caps in `shared/src/protocol.ts`. One `Limiter` DO (fixed name) stores only HMAC-hashed client keys, writes only when a counter changes.
- Room DOs store notes in SQLite since slice 2 (`noteStore.ts`, see below); slice 5 adds expiry. Per-socket state (hello, participant, token bucket) lives in the WebSocket attachment so it survives hibernation.
- Server assigns participant ids and `colourIndex`; `echo.from` comes from the socket. Names/text are cleaned with `cleanName`/`cleanText` (shared) and rendered as text only.
- No `console.` in `worker/src` (test enforces). Never log bodies, names, text, passcodes, codes or IPs.
- Web: `#/room/<code>`; sheets opened from a room show over it (`App.tsx` keeps the base page). The create passcode is never stored; `stickyard:name` holds the last-used name.

## Room expiry (v0.14.0)
- Idle rooms expire. Constants: `ROOM_IDLE_EXPIRY_DAYS` 7 and `ROOM_EXPIRED_CLOSE_CODE` 4410 in `shared/src/protocol.ts` (both sides use them); `ROOM_IDLE_EXPIRY_MS` (7 days) and `ALARM_RESET_SLACK_MS` (1 hour) in `worker/src/limits.ts`. Logic in `worker/src/expiry.ts` (`nextExpiryAlarm` pure, `readTombstone`, `writeTombstone`, `EXPIRED_REASON` "expired").
- Alarm rules (`Room.armExpiry`): when the LAST open socket closes (`webSocketClose`, `webSocketError`, and the rate-limit close; open sockets counted without the closing one, hibernated ones count, joined or not), read `getAlarm()`; set `now + expiry` only if there is none or it is earlier than `now + expiry - slack`, else write nothing. Joining never touches the alarm. `rowsWritten` counts a set alarm as 1 row (as billed).
- `Room.alarm()`: any open socket = do nothing, write nothing. Otherwise the room is buried as expired (since v0.15.0 through the shared burial path, see "Host, lock, timer" below; `deleteAll()` also deletes the alarm at our compatibility date, 2026-02-24 or later, and `worker/test/expiry.test.ts` checks wrangler.jsonc so lowering the date fails a test). Already buried = nothing.
- Tombstone: the constructor reads it first (`readTombstone`, read-only); a tombstoned room never builds a `NoteStore` (no migrate, no fresh board). `fetch` accepts the socket and closes it at once with 4410 "expired" (any protocol version, before hello); `webSocketMessage` does the same; closing it never sets an alarm. Origin and room-code checks still run in the Worker first.
- No protocol bump: no message changes, the close code is outside the message schema, and older pages see an ordinary close. No `SCHEMA_VERSION` bump: `expired_at` is a new key in the existing meta table and normal rooms never have it. Rollback: an older Worker would see a tombstoned room as new (no `schema_version`) and give it an empty board; old data is never resurrected.
- Web: `SocketHandlers.onClose(code?)`; `RoomSession.onClose` treats 4410, and only it, as final (`roomExpired`: status `expired`, retries/probes/listeners/queues/runs/history cleared, board emptied), on a first join or a reconnect. `RoomScreen` shows `Expired` (`data-session-expired`, h1 + `role=status` polite text `EXPIRED_TEXT`, a primary **Go to the start page** button), no board, no Rejoin. Help (sessions, connection) and About > Privacy say so.
- Existing rooms get their first alarm at their next last-close (rooms nobody visits again are not swept).

## Host, lock, timer, protocol v12 (v0.15.0)
- `PROTOCOL_VERSION = 12`; v11 pages get `version_mismatch`. Relay and plumbing; the host UI came in v0.16.0 (see "Facilitation UI").
- Host token (`worker/src/hostToken.ts`): stateless, `base64url(HMAC-SHA256(ROOM_SIGNING_KEY, "stickyard-host-v1:" + roomId))`, all 32 bytes (43 chars; domain differs from the room code's). `POST /rooms` returns `{ code, hostToken }`; nothing else ever returns it. Verified with `safeEqual` only. The Worker tells the room its id in `ROOM_ID_HEADER` (`x-stickyard-room-id`, always overwritten by the Worker); the room keeps it in the socket attachment.
- Client: `claimHost { token }` (after joined), `lockSet { locked }`, `timerStart { durationMs }` (`TIMER_MIN_MS` 1 s to `TIMER_MAX_MS` 3 h, outside = bad_message, not clamped), `timerStop`, `endSession`; all strict. Server: `hostGranted`, `participantUpdated { participant }`, `lockChanged`, `timerChanged { timer: null | { startedAt, durationMs, serverNow } }`, `sessionEnded`. Errors: `bad_host_token`, `not_host`, `board_locked`. Participants carry `host` (server-set; attachments from before v12 default false). `joined` carries `locked` and `timer` (same handler step as the snapshots, so nothing lands between them).
- claimHost: right token = `participant.host` in the attachment (survives hibernation), `hostGranted` to the claimer, `participantUpdated` to the others (once). Wrong token = `bad_host_token` and a violation (`Room.violation`, shared with rate limits). Several sockets may be host. Host-only messages from anyone else: `not_host`, nothing written.
- Lock: `BOARD_WRITES` in shared (a `Record` over every client message type; a test checks the classification) marks the 13 board-changing types. While locked, a non-host's are refused in `Room.handle` before any handler: `board_locked` with `refOf(message)` (clientRef / noteId / noteIds / frameId), nothing read, written or relayed, still spending rate tokens. Hosts, chat, join and leave are never blocked.
- Persistence: meta keys `locked` (0/1), `timer_started_at`, `timer_duration_ms` (`NoteStore.getMeta` / `setMeta`, written only on change; timer keys in one transaction). No `SCHEMA_VERSION` change (additive keys). Loaded in the constructor; cleared by any burial.
- End session: `sessionEnded` to everyone, then `Room.buryNow("ended")`, every socket closed with `ROOM_ENDED_CLOSE_CODE` 4411 "ended", then `finishBurial`. Burial (also expiry): step 1 in one `transactionSync` drops every table but meta, empties meta and writes the tombstone (`clearToTombstone` in `expiry.ts`); step 2 `deleteAll()`; step 3 the tombstone again. Tombstones: `expired_at` (4410) or `ended_at` (4411); `readTombstone` returns `{ kind, at }`. A crash between steps 2 and 3 leaves an empty room, never the old data.
- Web: `STORAGE_KEYS.hostTokenPrefix` + `hostTokenKey(roomId)` (`stickyard:host:<room id>`), written by the start page after creation, read by `useRoom` (`hostToken` / `forgetHostToken` session options), `removeKey` never throws. `RoomSession` sends `claimHost` after every `joined` (first join and reconnects) when a token is stored; `bad_host_token` forgets it quietly; 4410, 4411 and `sessionEnded` forget it too (`roomGone`). `RoomView` / `roomStore`: `isHost`, `locked`, `timer` (`RoomTimer` with `offsetMs` = serverNow minus arrival time; `timerRemainingMs(timer, now)`). `board_locked` rolls back with `NOTICES.locked`; `not_host` shows `NOTICES.notHost`. Status `ended` shows the `Gone` page (`data-session-ended`, `ENDED_TEXT`). The token is never shown, put in a URL, copied by Copy link / Copy details, or sent anywhere but `claimHost`.
- Since v17 (v0.25.0) `join` may carry the page's client key and `Room.join` awaits the writer id before the joined step; every message to a socket goes through `Room.send` / `Room.broadcast`, which filter note content per recipient (notes.md "Silent brainstorm").
- Reconnect: `PROBE_AFTER_FAILED_OPENS` raised from 3 to 5 (a relay restart or deploy of about 10 s now recovers on the normal backoff).

## Reactions: rate bucket, caps and burial (protocol v20, v0.33.0, part 1 of 2)
- `REACTION_LIMITS` (`worker/src/limits.ts`): 4 a second, burst 12, per socket, in the attachment (`reactTokens`, `reactAt`; defaults keep older attachments readable). A `reactionSet` is parsed first and spends only this bucket, like cursors and viewports, so reactions never starve edits; over it: `rate_limited` with `noteId`, counted as a violation. Then it is handled by `handle` like any other message.
- Caps live in shared (`MAX_REACTIONS_PER_ROOM` 2000, `MAX_REACTIONS_PER_REACTOR` 100); refusals are error replies (`reactions_full`, `reactor_full`), never a throw.
- Burial (End session, idle expiry) drops the `reactions` table with every other table; nothing new in meta. Nothing about who reacted is logged (no `console.` in `worker/src`, as before).

## Connectors: rate bucket, cap and burial (protocol v21, v0.35.0, arrows part 1 of 2)
- `CONNECTOR_LIMITS` (`worker/src/limits.ts`): 4 a second, burst 100 (a whole room's worth, so a page can delete or re-add every connector at once), per socket, in the attachment (`connectorTokens`, `connectorAt`; defaults keep older attachments readable). A connector message is parsed first and spends only this bucket, like reactions; over it: `rate_limited` with `clientRef` or `connectorId`, as a violation. Then it goes through `handle` (the lock, then a silent round's refusal, then `handleConnector`).
- Cap `MAX_CONNECTORS_PER_ROOM` 100 in shared (`connectors_full`). Burial drops the `connectors` table with every other table. Details in connectors.md.

## Groups: rate buckets, cap and burial (protocol v22, v0.37.0, structure part 1 of 3)
- `GROUP_LIMITS` (`worker/src/limits.ts`): 2 messages a second, burst 60 (every group ungrouped and re-added at once), and 10 member ids a second, burst 250 (every note and shape), per socket, in the attachment (`groupTokens`, `groupAt`, `groupMemberTokens`, `groupMemberAt`; defaults keep older attachments readable; a clock that went backwards refills nothing). A group message is parsed first and spends only these; over either: `rate_limited` with `clientRef` or `groupId`, as a violation, spending nothing. Then `handle` (the lock, then a silent round's refusal, then `handleGroup`).
- Cap `MAX_GROUPS_PER_ROOM` 30 in shared (`groups_full`). Burial drops `groups` and `group_members` with every other table. Details in groups.md.

## Hardening: the load harness (v0.39.1)
- `dev/load/` (dev only; never bundled): `npm run load` starts `wrangler dev` on 127.0.0.1:8799 (`relay.ts`: fake `--var` secrets, throwaway `--persist-to`), signs room codes and host tokens with the fake key (creation is capped at 5 a day per client), and runs `scenarios/*.load.ts`: pages are the web's own `RoomSession` over Node's WebSocket with a localhost Origin (`harness.ts` `Page`), raw protocol clients are `Raw`; every frame is recorded per recipient. `target.ts` `localTarget` refuses anything but http/ws on 127.0.0.1, localhost or [::1] (tested in the root `npm test`). Scenario 6 runs its own relay on 8798 to stop and restart it. Reports go to `dev/load/out/report.jsonl` (gitignored).
- `worker/test/budget.test.ts` (normal worker suite): the scripted two-hour, 12-person session's rows on the real Durable Object (`SESSION` holds the plan); rate buckets are refilled between actions so it runs in seconds. Results and the arithmetic: LIMITS.md "Hardening findings".
