## Reconnect and presence (v0.13.0)
- Web only, no protocol or stored-schema change. Reconnect lives in `RoomSession` (same session, so the board, chat and viewport stay): pure rules in `connection/reconnect.ts` (`backoffDelay` 1 s doubling to `RECONNECT_MAX_DELAY_MS` 30 s, ±20% jitter; `RECONNECT_MAX_ATTEMPTS` 8 then phase `offline`; `PROBE_AFTER_FAILED_OPENS` 5 (3 before v0.15.0) sockets that never opened → `checkHealth` (`probeHealth` in `connectionCheck.ts`, GET /health) then `checkCode` (/rooms/check); health down → phase `limit`: one probe every `LIMIT_RETRY_MS` 60 s while visible, at most `LIMIT_MAX_PROBES` 60, no sockets; `HIDDEN_GRACE_MS` 60 s then tries wait for visible; event-started tries `MIN_TRY_GAP_MS` apart). `ConnectionEnv` (online/hidden/listen) is injected: `browserConnectionEnv` in `useRoom`, `STATIC_ENV` by default; `random` too.
- `RoomView.reconnect` `{ phase: reconnecting | network | offline | full | limit, attempt, max }` (null while joined). Status stays `disconnected` throughout; fatal outcomes keep their old states (`reload` for version mismatch or a newer relay, `invalid` for a link the relay refuses); `room_full` on a reconnect is phase `full` (no auto retry, Rejoin). `online` restarts the sequence (not for `full`); `offline` while joined drops at once (phase `network`). `rejoin()` restarts now; it uses `storedName` (`stickyard:name`), else the name it joined with. Each socket's events are tagged (`socketGen`): a replaced socket's late events are ignored.
- The drop (`dropped`): counts my unconfirmed work with `unsavedKeys` (pending adds/deletes, held items, `History.pendingKeys()`; items of a template, restore, delete or clear run are left to their own reports), then `discardUnconfirmed` (board back to confirmed; drafts kept), one `dropReport` (`DROP_TEXT.unsaved(n)`, cleared by the next note action). Queued itemsAdd, clear frames, abandoned sets and the history all go; runs end partial as before. A draft on a note that goes becomes `orphanDraft` (`restoreDraft()` adds it back as a new note, `dismissDraft()`).
- Resync: on a reconnect `joined` updates you/participants but the board is live only at the `snapshot`, which replaces every note (`resyncNotes`, drafts kept by id); the following `framesSnapshot` replaces every frame (`resyncFrames`). No merge by rev; `synced` stays true (no refit). The history is cleared on the drop and on every snapshot. `RoomView.yourIds` holds every participant id of this visit (`authorName`, `countUnread` use it).
- Inline editing survives a drop read-only (`InlineText readOnly`), then commits normally; `uiStore.pruneSelected`/`pruneFrame` also drop an inline edit or edit request whose item is gone. `History.nextExpiry()` drives a session timer so Undo/Redo reasons refresh when a waiting change is given up on (the 0.12 stale-button bug).
- UI: `ConnectionBar` (top of the board's notice stack, `data-connection-status`, `role=status`, text from `rooms/connectionText.ts`; the limit state says "may be"), `data-drop-report`, `data-orphan-draft`. Tests: `test/reconnect.test.ts`, `test/reconnectSession.test.ts` (fake relay: `drop`, `failOpen`, `open`, `holdFrames`, `joinError`), UI in `roomsUi.test.tsx`.
- Presence: `presence/avatars.ts` (`avatarStack`: you first, `AVATAR_MAX` 4 places, the last is `+N` when more; `initials`, `truncateName` (`NAME_MAX_SHOWN` 16), `peopleLabel` for the button's accessible name) and `presence/AvatarStack.tsx` (md and up, in the Participants button; ring = `participantBorderClass`, size `--sy-avatar`); phones keep the count button. Toasts: `presence/toasts.ts` `summarizePresence` (a leave then a join of the same name, or a join then a leave of the same id, cancel out); the session batches (`TOAST_BATCH_MS` 1 s, a leave waits `LEAVE_GRACE_MS` 3 s, toasts `TOAST_GAP_MS` 2 s apart, shown `TOAST_SHOW_MS` 5 s) into `RoomView.presenceToast` (replaces `announcement`). No toast for yourself, the joined list, names back within `RESYNC_QUIET_MS` 15 s of your own reconnect or of their shown leave, or a leave while the same name is still here (a quick join still cancels a waiting leave). Rendered in the board's notice stack in an always-present `aria-live="polite"` region (`data-presence-toasts`), no buttons, `sy-fade-in`.

## Live cursors, protocol v14 (v0.19.0)
- `PROTOCOL_VERSION = 14`; v13 pages get `version_mismatch`. Client (strict): `cursor { x, y }` (finite numbers within the board ± `CURSOR_TOLERANCE` 64) and `cursorLeft {}`. Server (strict): `cursorMoved { id, x, y }` (whole units, `clampCursor` to the board) and `cursorGone { id }`. The id is the sender's participant id from its socket; name and colour come from the participant list. Both client types are `BOARD_WRITES: false` (a locked board still shows cursors). No stored-schema change.
- Relay (`room.ts` `cursor`): parsed before any rate budget; a valid cursor message spends `CURSOR_LIMITS` (limits.ts: 15/s, burst 20) and never `SOCKET_LIMITS` (malformed ones spend SOCKET_LIMITS and get bad_message). Over budget: dropped silently; past `maxSilentDrops` (100) in `dropWindowMs` (10 s) every further drop is a violation (`violation(..., null)`: counted, no reply). Forwarded at once to the other joined sockets: no coalescing, no timer, zero storage calls (tested by wrapping every storage method; `Room.timersPending` for the no-timer check). Before joining or alone: nothing sent. The attachment holds the bucket, drops and `cursorShown`; `hideCursor` sends `cursorGone` before `participant_left` (`leave`: close, error, rate-limit close) and for every shown cursor before `sessionEnded`. Costs in docs/LIMITS.md.
- Web pure rules: `cursors/cursors.ts` (`CURSOR_SEND_INTERVAL_MS` 100, `CURSOR_MIN_MOVE` 1, `CURSOR_IDLE_MS` 5000, `CURSOR_LABEL_CHARS` 12 = `--sy-cursor-label-max`; `cursorDecision`, `CursorSender` (leading + one trailing send, clock and timers injected), `pointerMaySend` (mouse, or a pen with no buttons: by pointer type, never screen size; touch never), `onBoardPoint` (off the board = leave), the cursor map (`moveCursor`, `removeCursor`, `idleCursors`, `nextIdleAt`), `placeCursor` (inside the visible area, scale 1/zoom, label flip), `cursorLabel`, `CursorSink`).
- Session: `shareCursor(x, y)` (only live, visible and with someone else here; rounded; straight to the socket, no view update or history), `hideCursor()` (cursorLeft once if shown; also on hiding the tab). `cursorMoved`/`cursorGone` are handled before the view machinery (never a view update) and go to `options.cursors`; my own ids and unknown participants are ignored; `participant_left` removes; drop, close, roomGone, every `joined` and a resync `snapshot` clear.
- Stores: `cursors/cursorStore.ts` (`useCursors`, `cursorSink`; one idle timer, nothing ticks while nothing moves); `cursors/prefs.ts` (`useCursorPrefs` show/share, `STORAGE_KEYS.showCursors` / `shareCursor`, "on"/"off", written only on change).
- Page: `cursors/useCursorSharing.ts` in `BoardCanvas` (md and up: pointermove → `screenToFlowPosition`; pointerleave, window blur, hidden tab and Share off → leave). `cursors/CursorLayer.tsx` inside `<ReactFlow>` via `ViewportPortal` (`data-cursor-layer`, aria-hidden, pointer-events none, `.sy-cursor-layer` z above every note); one memoised `CursorMark` per id reads only its own entry, so notes never re-render (render-count test mocks `NoteNode`). Inline SVG arrow: `--sy-cursor-outline` under `--sy-cursor-halo` (one of them 3:1 on every note, frame header, board and canvas colour, both themes, tested), fill = participant colour; label `bg-participant-N` with `--sy-cursor-label-fg` (4.5:1, tested). `--sy-duration-cursor` / `--sy-cursor-fade` are 0 under reduced motion. Phones draw with `data-compact` (smaller arrow and label) and never send.
- Participants sheet: `CursorSection` with two `role=switch` checkboxes (Show other people’s cursors, Share my cursor). Help: Participants topic, Cursors section. Privacy: pointers live, never stored; the switches stored here.
- Tests: `shared/test/cursors.test.ts`, `worker/test/cursors.test.ts`, `web/test/cursors.test.ts`, `web/test/cursorsSession.test.ts` (includes a two-page relay), `web/test/cursorsUi.test.tsx`.

## Navigation: last known pointers (v0.24.0)
- Web only. `CursorSink` gains `left(id)`: the session calls it on `participant_left` (was `gone`). `cursors.ts` `LastPositions`, `rememberPosition`, `forgetPosition` (pure). `cursorStore` keeps `lastSeen` beside `cursors`: `moved` updates both; `gone` (cursorGone) and the idle fade touch only `cursors`; `left` removes both; `clear` (every `joined`, drop, close, resync `snapshot`) empties both, so a reconnect forgets every position. Never stored; tracked whatever the Show switch says (the switch only hides `CursorLayer`). Phones receive pointers, so Go to works there.
- Participants (`rooms/ParticipantsPage.tsx`, the same component as the phone sheet and the md panel): each other person's row has `GoTo` (`data-goto`, label "Go to <name, 16 chars>’s pointer", `aria-disabled` with a visible `JUMP_HINT` reason via `aria-describedby` until `lastSeen` has them). A press closes the sheet (`closeSheets`) and calls `uiStore.requestJump`; the board does the rest (canvas.md "Navigation"). Tests: `test/lastSeen.test.ts` (fade, cursorGone, leave, reconnect, Show off, no `setItem`), `test/navigationUi.test.tsx`.
