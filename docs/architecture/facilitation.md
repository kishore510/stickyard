## Facilitation UI (v0.16.0)
- Web only: the protocol v12 messages from v0.15.0 (no protocol, stored-schema or worker change). `RoomSession` host commands: `startRoomTimer(ms)` / `stopRoomTimer()` (the private `startTimer` is the join timeout), `setLock(locked)` (not optimistic: `RoomView.lockPending` until `lockChanged`, a `not_host` or a drop; a second press while waiting sends nothing), `endSession()` (refused while a run is going: itemsAdd, restore, clear, template). All refuse (nothing sent) for a guest or while disconnected (`canHost`). Published to `roomStore` with `lockPending`, `endReason`.
- Timer: pure `timer/timer.ts` (`remaining(timer, now, offsetMs)` from timestamps, capped at the duration; `formatRemaining` mm:ss / h:mm:ss, rounded up; `timerPhase` running / final (last `FINAL_MS` 60 s) / finished; `chipVisible` until `FINISHED_HIDE_MS` 10 min after the end; `timerAnnouncement` (start, last minute, end, once each); `durationLabel`, `parseMinutes` (relay bounds), `stopNeedsConfirm`, `TIMER_TEXT`). `timer/useNow.ts` ticks once a second only while visible, and at once on `visibilitychange`. `timer/TimerChip.tsx` in the top bar's nav for everyone (`data-timer-chip`, `data-phase`; phones `data-compact`, no controls; host from md up: Restart/Stop `CommandButton`s), states by text + tokens, no animation; one always-present polite region `data-timer-announcer` (the countdown is `role=timer`, not live). Host controls: palette "Facilitation" category (`facilitationTiles` via `fromRoom`, host only, `surfaces: ["panel"]`; `TIMER_TILE` → `PaletteActions.openTimer` → `uiStore.timerPickerOpen`), `timer/TimerPicker.tsx` (a `Sheet` with `timer/TimerForm.tsx`: presets + minutes field, "replaces" note), `timer/controls.ts` `useTimerControls` (Stop confirm). `PaletteRoomState.isHost`, `PaletteContext.timerReason`.
- Lock: pure `facilitation/lock.ts` (`LOCK_TEXT`, `lockedOut` = locked and not host, `withLock(reason, s)` puts the lock's reason on any control while connected, `lockToggle`, `lockAnnouncement`, `END_SESSION_CONFIRM`, `endSessionReason`, `confirmEndSession`). `RoomBoard` wraps every reason (palette tiles, Duplicate, BoardBar `lockedReason` for Delete/Order/Arrange/Grid, Properties `locked` → read-only fields + `data-locked-reason`, Clear board), `BoardCanvas editable` false; `RoomSession.historyReasons` gives Undo/Redo the lock's reason. Courtesy only: `board_locked` rollbacks still apply. `facilitation/LockNotices.tsx` (first in the board's notice stack): the guest's banner `data-lock-banner` (no dismiss) and an always-present polite `data-lock-announcer`. Host: BoardBar "Session" group (`session` prop: `data-lock-toggle` labelled Lock board / Unlock board / Locking… / Unlocking…, `data-locked-indicator` "Locked").
- End session: Properties board summary (host, nothing selected, md up) under Clear board; phones: `ParticipantsPage` `SessionSection` (host, below md: timer form inline, Restart/Stop, Lock, End session). After `sessionEnded` the existing ended page shows and the host key is forgotten.
- Host markers: `ParticipantsPage` `data-host-badge` "Host" (text); `AvatarStack` faces are `role=img` named `avatarName` ("Sam, host") with a `Crown` mark (`data-host-mark`).
- Tests: `test/timer.test.ts`, `test/facilitationTimer.test.tsx`, `test/facilitationLock.test.tsx` (shared helpers in `test/helpers/ui.tsx`: fake socket and fetch, `inRoom({ host, isWide, locked, timer, notes })`), session cases in `test/host.test.ts`.
- Top bar fit (found in Chromium: the timer chip and the Session group overflowed at 1280): History, Edit and Order are icon-only at every width (their tooltips name them); `MEDIA.wideDesktop` (xl) decides the rest: from xl Order is its own group, the host's Session group is inline (Lock with its label + `data-locked-indicator`), and the chip has Restart/Stop; below xl Order folds into the Arrange panel, Session is one disclosure button (`BarGroup.badge` keeps "Locked" beside it) whose panel also holds Restart/Stop, and the chip shows only the time. The wordmark is visually hidden below lg (`Logo`). Measured: the bar needs 632/399/399 px of a 818/646/476 px slot at 1280/1024/768. The notice stack's "can't add notes" reason is suppressed while the guest's banner shows.
- LIMITS.md: no change (no new messages; the timer ticks locally; the lock and timer cost what v0.15.0 recorded).

## Dot voting, protocol v13 (v0.17.0)
- Relay and plumbing (the UI came in v0.18.0, see "Dot voting UI"). `PROTOCOL_VERSION = 13`; v12 pages get `version_mismatch`.
- Shared (`protocol.ts`): `VOTE_BUDGET_MIN/MAX/DEFAULT` 1/20/5, `MAX_VOTERS_PER_ROUND` 40, `VOTER_KEY_MIN/MAX_LENGTH` 22/64 (base64url), `VOTING_STATES` off | open | closed, `votingSchema { state, budget, round }`. Client (strict): `claimVoter { key }`, `voteSet { noteId, count }` (0 to 20), `voteStart { budget }` (outside 1..20 = bad_message, not clamped), `voteStop`, `voteClear`; the last three are in `HOST_ONLY`; all five are `BOARD_WRITES: false` (a locked board still takes votes). Server (strict): `voterGranted { remaining, mine }`, `votingChanged { voting }`, `voteConfirmed { noteId, count, remaining }`, `votesRevealed { round, totals }` (non-zero totals, note creation order). Errors: `voters_full`, `over_budget`, `voting_closed`, `no_voter` (vote refusals carry `noteId`). `joined` carries `voting`.
- Voter id (`worker/src/voterId.ts`): `base64url(HMAC-SHA256(ROOM_SIGNING_KEY, "stickyard-voter-v1:" + roomId + ":" + key))`, null without a key or room id. Kept in the socket attachment (`voterId`, survives hibernation) and the votes table; the raw key is never stored, echoed or logged (tested over tables, attachments and every outbound message). Same key = same voter (reload, second tab, reconnect). Cap: a new voter is refused with `voters_full` when 40 are known this round (voters with votes, plus voters claimed on other open sockets); `voteSet` re-checks as a backstop.
- Room (`room.ts`): `claimVoter` (after joined; writes nothing), `voteSet` (order of checks: not open = `voting_closed`, no claim = `no_voter`, unknown note ignored, total over budget = `over_budget`; stored only when it changes; `voteConfirmed` to every open socket of that voter, nothing to anyone else), `handleVoting` (voteStart: new round, all votes deleted, round + 1; voteStop: closed, then `votingChanged` and `votesRevealed` to everyone; voteClear: votes deleted, off; nothing to change = sender answered only, nothing written). The voting state is in memory, loaded from meta (`voting_state` 0/1/2, `voting_budget`, `voting_round`; bad values take defaults). Joining while closed: `votesRevealed` right after `framesSnapshot`, same handler step; while open, nothing about votes. `refOf(voteSet)` = `{ noteId }` (rate_limited rollbacks).
- Stored schema `SCHEMA_VERSION = 8`: `votes (voter_id, note_id, count)`, primary key voter + note, every column with a DEFAULT. `NoteStore` keeps a vote cache (`votesOf`, `usedBy`, `voterIds`, `setVote`, `totals`, `setVoting(meta, clearVotes)` in one transaction). Every note delete (`delete`, `applyBatch`) deletes that note's votes in the same transaction (dots refunded, nothing broadcast). Rows for notes that aren't here (left by v12 code after a rollback) or with a count outside 1..20 are skipped on load. Tested against `worker/test/fixtures/schemaV7.ts`, including v12's note insert/delete on schema 8. Burial drops the table with the others (tested).
- Row writes (measured): new vote 2, changed count 1, count to 0 = 1 (delete), same count 0; voteStop 1; voteStart/voteClear 1 per deleted vote + changed meta keys. docs/LIMITS.md has the rest (largest `votesRevealed` 8,460 bytes).
- Web: `voting/voterKey.ts` (`newVoterKey` = 16 bytes from `crypto.getRandomValues`, base64url; `voterKeyFor(roomId)` makes and stores it under `voterKeyKey(roomId)` = `stickyard:voter:<room id>` (`STORAGE_KEYS.voterKeyPrefix`), a fresh unstored one if storage fails; `forgetVoterKey`). `useRoom` passes `voterKey` / `forgetVoterKey`; `RoomSession` sends `claimVoter` after `claimHost` on every joined, forgets the key in `roomGone` (4410, 4411, sessionEnded).
- `RoomView` / `roomStore`: `voting`, `isVoter`, `myVotes` (confirmed + waiting votes on top), `remaining`, `results` (closed only, `VoteTotal[]`). Session internals: `votesConfirmed`, `votesLeft`, `votesPending` (per note, in send order; a `voteConfirmed` from another tab leaves them alone). `votingFrom` clears my votes and results on a new round or off. `voteSet(noteId, count)` is refused here with a notice (`NOTICES.voteOffline`, `votingClosed`, `noVoter`/`votersFull`, `overBudget`) and nothing sent, otherwise shown first then sent; relay refusals (`VOTE_REFUSALS`, and `rate_limited` on a note with a waiting vote) roll back the oldest waiting vote with one notice and never touch the board. `pruneVotes` (after each message, once synced and not resyncing) drops gone notes from my votes (dots back) and from results. A drop clears waiting votes and `isVoter`; the reclaim's `voterGranted` resyncs. Votes never enter the undo history. Host: `startVote(budget)`, `stopVote()`, `clearVotes()` (`canHost`).
- Privacy (About) describes the voting key and anonymous votes (still true with the v0.18.0 UI).
- Tests: `shared/test/voting.test.ts`, `worker/test/voting.test.ts`, `web/test/voting.test.ts` (fake relay: `voting`, `votes`, `refuseVote`, `room(..., setup)`), `web/test/votingUi.test.tsx`.

## Dot voting UI (v0.18.0)
- Web only, on the v13 plumbing (no protocol, stored-schema or worker change). Pure rules and texts in `voting/voting.ts` (tested in `test/votingRules.test.ts`): `stripText`, `voteAnnouncement` (start, reaching 0, stop; never per dot, nothing on joining), `voteReasons` (`VOTE_HINTS`, precedence: not open, offline, unsaved note, `votersFull`, not granted ("Joining the vote…"), then no dots left / nothing to remove; the board lock is deliberately not an input), `reasonLines`, `voteKey` (D adds, Shift+D removes, on a focused note; not with Ctrl/Cmd/Alt; `+`/`-` stay zoom), `hostVoteReasons({ blocked, state })` (`blocked` = roomStore `endReason`), `BUDGET`/`validBudget`/`stepBudget`, `resultRows` (count desc, ties in the relay's order, gone notes left out, `top` = tied for most), `noteTitle`, `totalsOf` (cached per results array), `voteLabel`, confirm helpers.
- Session (web): `RoomView.votersFull` (claim or vote refused with voters_full; cleared by voterGranted, a drop, a new round); a page without a voter re-sends `claimVoter` when a new round opens; `startVote`/`stopVote`/`clearVotes` refuse while a run is going (`running()`, shared with `endSession`). roomStore adds `votersFull` and `resultRows` (built in `RoomScreen` by `useResultRows`, kept the same object while unchanged so drags don't republish).
- Board: `VotingStrip` (`data-voting-strip`, plain text, no dismiss, `action` = Show results while closed) and the one polite `data-vote-announcer`, after the lock banner in the notice stack. `NoteNode` reads votes from roomStore (`voting/NoteVotes.tsx`): `VoteBadges` (`.sy-vote-badges` row above the note, between the top-left handle and the select tick; `data-my-dots` with a dot icon, `data-vote-total` "Total N" and `data-top-voted` filled; `aria-hidden`, the words go in the note's `aria-label` via `useNoteVoteLabel`) and, for the one selected note while open, `VoteControls` (a React Flow `NodeToolbar` below the note: screen-sized, `nodrag nopan nowheel`, z 4). Tokens `--sy-vote-badge`, `--sy-vote-badge-gap`, `--sy-vote-controls-offset`.
- `voting/VoteButtons.tsx`: `VoteButtons` (− count +, `size-touch`, off = `aria-disabled` + `aria-describedby` to a visible `data-vote-reason`), `voteFromKey` (NoteCard calls it before the editable check, so the lock never blocks it), `VotesSection` (`data-votes-section`, "Votes", first in `NoteFields`: Properties and the phone editor sheet; hidden while voting is off). Phones on a locked board vote from the selected note's controls (the sheet needs an editable board).
- Host: `voting/HostVoting.tsx` `HostVotingControls` (`data-host-voting`; Dots each stepper, Start voting / Start a new round (confirm when not off), Stop and reveal (confirm "End voting and show results to everyone?"), Clear votes (confirm); reasons as `data-host-vote-reason`). In `BoardBar`'s Session group: from xl a nested "Voting" `CollapsedGroup`; below xl inside the Session panel. Phones: the Session section in Participants. No voter count (the relay sends none).
- Results: `voting/Results.tsx` `ResultsList` (`data-results`, rows `data-result-row` with `data-result-title` (truncate, plain text), `data-result-top`, `data-result-count`; "No votes were cast."), first in the Properties board summary, and the `#/results` sheet (`Sheet` kind `results`, `ResultsPage`). A row calls `uiStore.requestReveal(id)` (selects; `RoomBoard` reveals via `canvas.reveal`). Show results: phones open the sheet; md and up clear the selection and expand Properties.
- Tests: `test/votingRules.test.ts`, `test/votingBoard.test.tsx` (part 1), `test/votingResults.test.tsx` (part 2), session cases at the end of `test/voting.test.ts`. `inRoom` takes `voting`. Help: `dot-voting` topic; Running a session has a Dot voting section. LIMITS.md unchanged.

## Silent brainstorm, protocol v17 (v0.25.0, part 1 of 3)
- Relay and shared only; no web UI yet (parts 2 and 3). `PROTOCOL_VERSION = 17`; v16 pages get `version_mismatch` ("please reload"). Sealed notes, storage and the leak inventory: notes.md "Silent brainstorm: sealed notes and the leak inventory".
- Client (strict): `silentStart`, `silentReveal`, both in `HOST_ONLY` and `BOARD_WRITES: false` (a host may start a round on a locked board; the lock still blocks guests' notes as before). `join` takes an optional `key` (`clientKeySchema`, the voter key's format: the page's existing per-room key). Server (strict): `silentChanged { active, count }` (count = every sealed note in the room, one number), `notesRevealed { notes, final }` (1 to `REVEAL_CHUNK_NOTES` = 50 notes, creation order, `final` on the last chunk). `joined` carries `silent { active, count }` (from memory). Errors: `silent_active`, `no_writer`, `sealed_full`; `ITEM_REFUSALS` gains `no_writer` and `sealed_full`. `MAX_SEALED_PER_WRITER` 40.
- Writer id (`worker/src/writerId.ts`): `base64url(HMAC-SHA256(ROOM_SIGNING_KEY, "stickyard-writer-v1:" + roomId + ":" + key))`, null without a key, signing key or room id. `Room.join` works it out before anything is sent (one await, then the whole join in one step, re-reading the attachment), so every snapshot (join, reconnect, second tab, wake) already holds that writer's sealed notes. Kept in the attachment as `writerId` (about 600 bytes for the largest attachment, far under 16 KiB; survives hibernation as is: it can't be re-derived, since the key is never stored). Never sent, never logged; stored only on sealed notes; its domain differs from the voter id's, so the two stored ids can't be matched.
- State: meta `silent_active` (0/1) and `silent_round` (rounds started), loaded in the constructor, cleared by burial. `Room.silent`, `silentView()`, `broadcastSilent()`.
- Rules (`room.ts`): `silentStart` while one runs: `silent_active`, nothing written; otherwise both keys in one transaction, then `silentChanged` to everyone. A note added while active (`noteAdd`, `itemsAdd` notes) is sealed with the sender's writer: none = `no_writer` (itemsAdd: per note, frames and shapes still added); at 40 = `sealed_full`; the 200-note room cap counts sealed notes. Its messages reach only the writer's sockets (all of them); everyone gets `silentChanged` on each add or delete (one per message). Someone else's sealed note in edit, move, resize, delete, batch, order, frame carry or vote is ignored exactly as an unknown id (`noteFor`). Nobody can vote on a sealed note. While active, `frameMove` (live or final, anyone) and `voteStart` get `silent_active`; frame add, edit, resize and delete, shapes, chat, voteStop and voteClear are unchanged. The relay has no delete-all message (Clear board is a page-side run of noteBatch deletes), so stopping Clear board while silent is part 2's job. `silentReveal`: with none running, `silentChanged` to the sender only, nothing written; otherwise `NoteStore.reveal` (one transaction: sealed = 0, writer = NULL, 1 row per note, plus the flag), then `notesRevealed` chunks to everyone (no rev bump: a writer's copies have the same id and rev), then `silentChanged`. One way: a later round is a new round. End session and expiry drop sealed notes with everything else.
- The web (unchanged in part 1) ignores the new messages (they parse, and its message switch has no case for them; tested in `web/test/session.test.ts` "a v17 relay": joined with silent active and inactive, silentChanged, notesRevealed; a message it can't parse at all still means "please reload", never a crash), and doesn't send `key` yet, so it can't add notes during a round started by another client. Part 2: send `key` in `join` (the voter key), host Start / Reveal (warn on a locked board), the count, my sealed notes marked, `notesRevealed` applied once by id and rev, Clear board / frame drags / Start voting off while silent with the reason, Help.
- Costs in docs/LIMITS.md "Silent brainstorm". Tests: `worker/test/silent.test.ts`, `worker/test/sealed.test.ts`, `shared/test/silent.test.ts`.

## Silent brainstorm: which notes are mine, protocol v18 (v0.26.0)
- Relay and shared only (no stored-schema change, no web UI). `PROTOCOL_VERSION = 18`; v17 pages get `version_mismatch`. Server (strict): `silentMine { ids }` (0 to `MAX_SEALED_PER_WRITER` note ids), sent to the joining socket only, in the join step right after `shapesSnapshot` (before a closed vote's `votesRevealed`), and only while a round is silent: the socket's writer's own sealed notes in creation order, [] without a key. Nothing else changed: no message per add, the page derives the rest (every note add it hears about while a round runs is its own and sealed; a delete removes the id; `silentChanged` active false empties it).
- Why: found at the start of part 2. From v17 alone a page couldn't tell, after a reload, a late join or a new tab, which snapshot notes were its own sealed ones, so its sealed count, the 40-per-writer check and hiding vote controls on sealed notes would all be wrong there. Options and the choice are in PHASE_PLAN.md.
- The web (unchanged) ignores it; tested in `web/test/session.test.ts` "a v17/v18 relay". Part 2 (web) builds on it.
