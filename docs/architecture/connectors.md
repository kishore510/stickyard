# Connectors (arrows)

Architecture notes for connectors. Sections are in build order and keep the version that introduced them; later sections can override earlier ones. A quoted section name may live in another file: see `docs/architecture/README.md`.

## Connectors, protocol v21 (v0.35.0, arrows part 1 of 2)
- Relay and shared only; no web UI yet (part 2). `PROTOCOL_VERSION = 21`; v20 pages get `version_mismatch` ("please reload"). Stored `SCHEMA_VERSION = 12`.
- One new object, the connector (`connectorSchema`): `{ id, start, end, route, dash, width, ink, startHead, endHead, rev, authorId }`. Each end is either free `{ x, y }` (whole board units, edges included) or bound `{ item, anchor }` (a note's or shape's server id; `CONNECTOR_ANCHORS` auto | top | right | bottom | left). A bound end never carries coordinates, on the wire or in storage: every page works its point out from the item's current box, so moving or resizing an item writes nothing for its connectors. Bindable: notes and shapes only (never frames or connectors). Keys only, never CSS: `CONNECTOR_ROUTES` straight | elbow, `CONNECTOR_DASHES` solid | dashed | dotted, `CONNECTOR_WIDTHS` thin | medium | thick, `CONNECTOR_INKS` (= `SHAPE_STROKES`: neutral plus the six note hues), `CONNECTOR_HEADS` none | arrow (one per end). `CONNECTOR_DEFAULTS` (straight, solid, medium, neutral, no start head, arrow at the end) is what part 2 offers first and what storage fills in for missing style columns.
- No z: connectors are one fixed layer above frames and below notes and shapes (part 2 draws them there). They are not in the notes' and shapes' stacking space (`notesOrder` never names one).
- Client (strict): `connectorAdd { clientRef, start, end, ...every style field }` (full content), `connectorUpdate { id, start?, end?, ...style? }` (at least one field), `connectorDelete { id }`. A free end may be sent up to `CONNECTOR_TOLERANCE` (64) past an edge and fractional; the relay rounds and clamps it (`clampConnectorPoint`). Server: `connectorsSnapshot { connectors }` (strict, creation order, on every join right after `reactionsSnapshot`), `connectorAdded` (`clientRef` only to the sender), `connectorUpdated` (whole connector), `connectorDeleted { id }`. Errors: `connectors_full`, `unknown_item`; the error ref `connectorId` (refused update, delete, lock, rate). `itemsAdd` is unchanged: part 2 adds items first, then connectors with the returned ids.
- `BOARD_WRITES`: all three true (a lock refuses a guest's with `board_locked` and the ref; hosts go through). Not host-only. During a silent round all three are refused for everyone, the host too, with `silent_active` (checked in `Room.handle` before the handler, like `frameMove`): an arrow could point at notes others can't see.
- Refusals (`Room.refuseEnds`, in this order, nothing written or relayed): an end the message gives that is bound to anything but a note or shape on the board (an unknown or deleted id, a frame, a connector, and someone's sealed note, word for word) is `unknown_item`; both ends on the same item is `bad_message`; ends that resolve to the same whole-unit point (free and free after clamping, or a free end exactly on the bound anchor) are `bad_message`. A style-only update never re-checks the ends; an update that changes nothing writes and sends nothing; an unknown or deleted connector id is ignored silently (as for shapes).
- Last write wins in arrival order, every stored change bumps rev (the shapes pattern: no client rev; pages apply by rev).
- Geometry is one pure module, `shared/src/connectors.ts`, used by the relay now and the page in part 2: `anchorPoint(box, anchor, other)` (top / right / bottom / left: the middle of that side; auto: where the line from the box's centre towards `other` leaves the box, exact on that edge; `other` inside the box still gives the edge in its direction; `other` at the centre gives the top middle), `endReference(end, boxOf)` (what the other end aims at: a free point, a fixed anchor's point, an auto anchor's item centre, so two auto ends aim at each other's centres), `resolveConnector({ start, end }, boxOf)` (both points, or null when an item is missing), `clampConnectorPoint`, `isBound`. Every item kind is its box in v1 (an oval or diamond is joined at its box edge).
- The delete rule (`NoteStore.detachFrom`, called by `delete`, `applyBatch`, `deleteShape` and `applyShapeBatch`, so every note and shape delete path is covered: single, batch, Clear board's batches): each end bound to a deleted item becomes free at `clampConnectorPoint(anchorPoint(its box, its anchor, the other end's reference))`, computed from the boxes before the delete (two deleted items in one batch use each other's last boxes), one rev bump per connector, written in the same transaction as the item delete. The room then broadcasts the item's delete message and, after it, one `connectorUpdated` per changed connector. The relay has no Clear board message: Clear board is the page's batch deletes, so its connectors are detached like any other, and part 2's Clear board must also send a `connectorDelete` for each connector (`CONNECTOR_LIMITS` burst 100 allows them at once). A frame delete touches no connector. Burial (End session, idle expiry) drops the table.
- Sealed notes: a connector is never bound to one. A bind to a sealed note is `unknown_item` exactly as a random id, for everyone, its writer too; in practice sealed notes exist only during a round, when every connector message is `silent_active` first (and a bind to a sealed id gets exactly the reply a random id gets). `connectorsSnapshot`, `connectorAdded` and `connectorUpdated` are `carriesNoteContent` (a bound end names a note) with `scrubFor` entries that drop a connector naming a hidden note whole (a backstop); `connectorDeleted` names only the connector. `NoteStore.connectors()` also skips any row bound to a sealed note. The silent canary (`worker/test/silent.test.ts`) proves no connector message to anyone carries a sealed id or place.
- Stored schema 12: `connectors (id, start_item, start_anchor, start_x, start_y, end_item, end_anchor, end_x, end_y, route, dash, width, ink, start_head, end_head, rev, author_id)`, every column but the key with a DEFAULT (end columns NULL; style columns `CONNECTOR_DEFAULTS`; rev 1; author ''). A bound end stores item and anchor with NULL x, y; a free end NULL item and anchor. Additive migration 11 -> 12 (`CREATE TABLE IF NOT EXISTS`, no other table touched). `NoteStore`: `allConnectors`, `getConnector`, `connectorCount`, `boxOf` (a note that isn't sealed, or a shape), `insertConnector`, `updateConnector`, `deleteConnector`. Loaded once per wake after notes and shapes; rows that don't validate (unknown keys, half an end, a bad anchor, no author) are skipped, a free end off the board is clamped (in memory), and a connector bound to an item that isn't here (v0.34.0 code deleting it after a rollback) is skipped. Tested against `worker/test/fixtures/schemaV11.ts` with v0.34.0's exact note and shape statements.
- Rollback: a v0.34.0 Worker never reads the table; while it runs, deleting a note or shape doesn't detach its connectors, and after rolling forward those connectors are skipped on load (hidden, never an error). See PHASE_PLAN.md "7b Arrows".
- Rate: `CONNECTOR_LIMITS` 4/s, burst 100, per socket, never `SOCKET_LIMITS` (rooms.md "Connectors: rate bucket, cap and burial"). Cap `MAX_CONNECTORS_PER_ROOM` 100. Costs in docs/LIMITS.md "Connectors".
- Web (part 1): only what the version bump forces. The join sends protocol 21; `RoomSession.onMessage` validates the four connector messages and returns before `handle` (no view update, no notice, no error); a connector message that doesn't validate is "please reload" like any other. The test helpers' fake relay and `joinRoom` send `connectorsSnapshot` like the Worker.
- Tests: `shared/test/connectors.test.ts` (schemas, keys, sizes, `anchorPoint`, `resolveConnector`, `clampConnectorPoint`), `worker/test/connectors.test.ts` (add, update, delete, clamps, refusals, cap, lock, silent round, sealed binds, join order and a mid-round join, the delete rule on every path with one-transaction checks, moves write nothing extra, burial, rate with explicit time budgets, row costs, migration 11 -> 12), the silent canary and `worker/test/sealed.test.ts` samples, `web/test/session.test.ts` "a v21 relay".
- For part 2: draw connectors from `resolveConnector` with the page's own live boxes (during a drag the relay sends nothing for connectors); treat `connectorUpdated` after a delete as the server's word; Clear board, duplicate and undo must send connector messages themselves (add items first, then connectors with the returned ids); a refused add or update names `clientRef` / `connectorId` for rollback.

## Arrows: the UI (v0.36.0, arrows part 2 of 2)
- Web only (protocol v21, stored schema 12 unchanged). Tests: `web/test/connectorsBoard.test.ts` (reducers), `connectorsGeometry.test.ts` (re-route, snap, attach, free, marquee, labels, freed counts), `connectorsPace.test.ts` (pacing on a fake clock, replayed through the relay's own bucket read from `worker/src/limits.ts`), `connectorsSession.test.ts` (fake relay with the Worker's delete rule), `connectorsUi.test.tsx`, `connectorsExport.test.ts`.
- Model `connectors/board.ts` (the shapes pattern): `Board.connectors` / `connectorsRemoved` (`BoardConnector { connector, confirmed, clientRef }`). `applyConnectorsSnapshot` replaces every confirmed arrow (pending adds stay), `applyConnectorUpdated` by rev (equal or older ignored; unknown ids ignored), `applyConnectorAdded` (by clientRef in place), `applyConnectorDeleted`; optimistic `addConnectorLocal`, `updateConnectorLocal`, `deleteConnectorLocal`; `rollbackConnector`, `rejectConnectorAdd`, `discardUnconfirmedConnectors` (in `resync.discardUnconfirmed`; `unsavedKeys` counts arrows); `renameItemInConnectors` (an item's server id reaches the ends of arrows still waiting here); `connectorChanges` (ends by value).
- Geometry `connectors/geometry.ts`: `boxOfBoard` (shown notes and shapes, plus ones deleted here and waiting, so an arrow stays put until the relay's freed end arrives; the layer also keeps the last drawn points), `resolveShown` (= shared `resolveConnector`), `routePoints` (straight; elbow: one bend each way through the middle, horizontal first when wider), `snapEnd` (topmost confirmed note or shape within `SNAP_PX` 24 screen px; a side's middle within `ANCHOR_PX` 16 gives that anchor, else auto), `endAt` (bound, or `clampConnectorPoint`), `endsProblem` (same item, zero length, missing), `moveFreeArrow`, `reversedPatch`, `marqueeConnectors` (both ends inside), `connectorLabel` ("Arrow from Yellow note: … to a free end"; item text `truncate`d to 32, text only), `freedArrows`.
- Session (`RoomSession`): `addConnector`, `updateConnector`, `updateConnectors` (style for several, one step), `reverseConnectors`, `moveConnector` (both ends free, else `CONNECTOR_TEXT.attachedMove`), `deleteConnectors`; `deleteSelection` / `duplicateSelection` take `connectorIds`; `onConnectorConfirmed`. Refused up front with the reason (nothing sent): not live; a guest on a locked board (`LOCK_TEXT.reason`); a silent round, everyone (`SILENT_TEXT.on`); 100 arrows; both ends on one item; zero length; an end on an unsaved item. Relay refusals roll back with one calm notice (`connectors_full`, `board_locked`, `silent_active`, `rate_limited`, `unknown_item`); a clear's go in its report. Nothing is sent during a drag of anything: item moves re-route from live boxes, an end or line drag sends one `connectorUpdate` on release.
- Pacing `connectors/pace.ts`: every connector message goes through `ConnectorPacer` (`CONNECTOR_PACE` burst 96, 3.5 a second, a little inside the relay's 100 / 4), reset (full, queue dropped) on every `joined`, a drop and leaving. `whenSent(fn)` runs once the queue is out.
- Deletes: arrows first. `startRemoval` (Clear board, a selection delete) and an undo/redo plan queue their `connectorDelete`s and send the item deletes from `pacer.whenSent`, so no end of an arrow that's going is freed. `ClearRun.connectors`; reports name arrows (`removalReportFor` 4th part).
- History (`history/history.ts`): kind `connector`; fields are plain, ends JSON strings (`connectors/fields.ts`: `connectorFields`, `patchFromFields`, `contentFromFields`, `renameEndRefs`). `History({ renameRefs })` rewrites ends in every record and expectation when a note's or shape's id changes (an undo adding it back, then the relay's id). `recordRemove(..., relayChanges)`: an item delete records, for each arrow bound to it, a change whose `after` the relay makes itself (`relay` matcher: those ends are free; `after` becomes what was stored). Undo restores the items and, once the run's items have their ids, sends the re-attach; redo sends nothing for it (`ChangeStep.byRelay`) and waits for the relay. An arrow changed by someone else since is skipped and reported (`HISTORY_TEXT.conflicts`, appended to the restore report).
- Runs (`ItemsRun.arrows`): a duplicate's or an undo's arrows are added locally at once with ends on the items' local ids, and sent (paced) when the run's items are all answered (`flushArrows`); an arrow whose item wasn't added is dropped and counted. "Restoring N of M…" counts arrows. An undo that would pass 100 arrows is refused before the history moves (`CONNECTOR_TEXT.restoreFull`); Duplicate likewise (`duplicateFull`). Duplicate copies arrows whose ends are free (offset with the copies) or on selected notes and shapes (remapped to the copies); others aren't copied. One history step holds the copies and their arrows.
- Canvas: `connectors/ConnectorLayer.tsx` `ConnectorLayer`, an SVG in a `ViewportPortal` at `CONNECTOR_Z_INDEX` (-NOTE_Z_LIMIT - 1; frames moved to -2, the board to -3), above frames, below notes and shapes. Strokes are `non-scaling-stroke` (screen px from `--sy-connector-*`); heads and dashes sized in screen px; below `READABLE_ZOOM` 0.25 plain lines. Inks are `--sy-shape-<ink>-stroke` (3:1 on the board, both themes, the shapes test). Each arrow is a `g` (`data-connector-id`, `aria-roledescription="arrow"`, the label; md and up `role=button`, `tabIndex=0`, `aria-pressed`) with a transparent wide hit path (`nopan nodrag`, pointer events only md and up); selection halo and focus ring are export-skipped. `ConnectorOverlay` (z 150000, `data-connector-overlay`): the selected arrow's end handles (44 px targets) and snap points and the drawing preview. `DrawHandles` (the four side handles of one selected note or shape) sit in the arrows' layer, under notes, so the item's reaction and vote controls stay on top (found in Chromium).
- Drawing `connectors/useConnectorDrawing.ts` + `connectors/connectorUi.ts` (zustand: `draw` (armed style), `drawing`, `drag`, `announce`): a tile arms; a capture-phase press on the canvas starts (snapped), drag-release or a second click finishes with one `addConnector`; Esc cancels; the marquee stays off while armed. `ConnectorDrawHint` in the notice stack, `ConnectorAnnouncer` (polite; my own add and delete only).
- Selection: `uiStore.connectors` / `connectorSelected`, `selectConnector`, `toggleConnector`, `renameConnector`, `pruneConnectors`; marquee, Ctrl+A, `deleteKeyTarget` "connectors" (arrows alone: deleted without a confirm) or "selection". Delete confirms add `freedLine(n)` ("N arrows will keep a free end."): `confirmDelete`, `confirmDeleteNotes`, `confirmShapeDelete`, `confirmDeleteSelection` (`deleteCounts` `arrows`, `freed`).
- Palette: "Connectors" category (`CONNECTOR_TILES`: Arrow, Line, Elbow arrow; panel only), `PaletteActions.startArrow`, `PaletteContext.connectorReason`. Properties: `connectors/ConnectorFields.tsx` for one or several (route, dash, width, ink, heads, Reverse; `data-connector-reason` shows why it's off); the board summary says "N of 100 arrows". Reasons (RoomBoard `arrowReason`): disconnected, the lock, the silent round; tiles also at 100.
- Export: `exportItems` (PNG box includes arrow ends), `keepInExport` skips `data-connector-overlay/-handle/-snap/-preview`; Markdown "## Connections": `- A → B` from cleaned, escaped item text, "(free end)", nothing about style.
- Left out on purpose: labels, attaching to frames, waypoints or curves, frames carrying free arrows, arrow-key nudging, editing on phones, groups and stencils. `MAX_ZOOM` is 2, so "readable to 400%" is readable to 200%.
