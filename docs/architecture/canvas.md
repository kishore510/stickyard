# Canvas, panels, selection and arrange

Architecture notes, moved out of CLAUDE.md on 7 October 2026 so they load only when needed. Sections are in build order and keep the version that introduced them; later sections can override earlier ones. A quoted section name ("Frame multi-select") may live in another file: see `docs/architecture/README.md`.

## Board UX (slice 2.5)
- Canvas is React Flow (`@xyflow/react` 12, Chalkline's major), controlled: notes stay in `RoomSession`/`board.ts`; `web/src/canvas/nodes.ts` maps them to memoised nodes (reused while the entry is unchanged) and turns drag events into session moves. React Flow owns only the viewport and gestures. `NoteNode` (in `notes/NoteCard.tsx`) is `memo`; note actions come from a stable context.
- Flow units ARE board units. The one conversion, zoom limits, fit, pan extent, new-note placement and the tap/drag threshold are pure functions in `web/src/canvas/geometry.ts` (tested). `WHEEL_BEHAVIOUR` there flips wheel-pans to wheel-zooms. Server clamping is unchanged.
- Tool registry: `web/src/canvas/tools.ts` (`TOOLS`, each with `slots` per surface: `viewbar`, `ribbon`; the slice 2.5 rail is gone, see 2.6). `ToolBars.tsx` renders the view bar from `md` up and the ribbon below `md` (switched with `MEDIA.tablet`, never a user agent). New tool = one registry entry + its action in `ToolContext` (`canvas/RoomBoard.tsx`). Tool, last colour, selection and minimap choice live in `canvas/uiStore.ts` so a breakpoint switch keeps them; React Flow stays mounted so the viewport survives too. No placeholder tools.
- `canvas/RoomBoard.tsx` is lazy-loaded (React Flow isn't in the start page's bundle); `RoomScreen` preloads it when a room opens.
- Rooms are full-bleed (`Shell bleed`): no page scroll, no footer. Chat: `web/src/chat/ChatDock.tsx` (floating from `md`, a bottom sheet on phones opened from the top bar or menu); unread logic in `chat/unread.ts`. Participants: `#/participants` sheet (`rooms/ParticipantsPage.tsx`) with Copy link and Leave. Room state for the top bar, menu and sheets is published to `rooms/roomStore.ts` by `RoomScreen`.

## Palette and Properties panels (slice 2.6)
- Look and feel follow Chalkline's panels and phone drawer as closely as the stack allows (user request: consistency across the two apps). Check Chalkline (`~/projects/chalkline/src/editor/palette.tsx`, `Properties.tsx`) before changing panel UI.
- From `md` up the board is a flex row: palette (`aside[aria-label=Palette]`, left), canvas, Properties (right), all in `canvas/RoomBoard.tsx`. Both panels use `panels/SidePanel.tsx` (content gets the collapse button for its own header: the palette's segmented tab box, Properties' sticky underlined tab row; collapsed = slim strip with expand plus a compact version: palette tiles, a Properties button; `role=separator` resize handle with arrow/Shift/Home/End, double-click reset, and drag well past the minimum to collapse). `[` / `]` toggle them. Below `md`: no panels; the ribbon (Select/Hand, round primary **+** Add note, Fit), the non-modal add drawer (`AddDrawer`: search, a sideways row per category, tap to add, press-and-hold `--sy-long-press` to drag onto the board) and the editor sheet.
- Panel sizes: `panels/layout.ts` (pure: `PANEL_LIMITS`, `panelWidths` clamps to a third of the window and keeps `CANVAS_MIN`, `keyResize`, `tileColumns`, `parsePanelState`, `cornerLifted`), mirrored by `--sy-palette-*`, `--sy-properties-*`, `--sy-panel-*`, `--sy-tile-min`, `--sy-canvas-min` in tokens.css (test checks). Layout state: `panels/panelStore.ts`, saved under `STORAGE_KEYS.palettePanel` / `propertiesPanel` (layout only; About > Privacy says so).
- Palette registry: `palette/registry.ts`. `PALETTE_TABS` (a tab shows only when one of its categories has items: no Stencils tab until a stencil is registered), `PALETTE_CATEGORIES` `{ id, label, order, tab, items, fromRoom? }`, items `{ id, label, keywords, preview, payload, create(actions, at?), disabled(ctx) }`. `fromRoom(state)` is the dynamic selector for room-derived tiles (since v0.16.0 the host-only Facilitation > Timer tile uses it; `PaletteRoomState` has `isHost`). `palette/Palette.tsx` renders the panel content and the phone `AddSheet` from it; tiles click/Enter to add at the viewport centre, or drag onto the board (`geometry.dropPosition`, clamped).
- New object types (group box, connectors) need their own protocol-change slice first (the timer isn't a board object: it's room state, protocol v12; shapes came in protocol v15, see below); their tile is then one registry entry (in a new category). No placeholder tiles.
- Selection: a set of note ids (`canvas/selection.ts`, pure helpers) in `uiStore`; a real multi-select since 2.8 (see below); frames have their own set beside it since v0.20.0 (see "Frame multi-select"), and shapes a third since v0.21.0 (see "Shapes, protocol v15"). Click or focus selects, pane click or Esc clears, deleted notes are pruned, and `RoomSession`'s `onNoteConfirmed` renames a local id to its server id. Nodes carry `data.selected`.
- Note size: `notes/size.ts` `noteSize(note)` is the one lookup (the note's own `w`/`h` since 2.7; the default for a spot without a note); nodes, fit, reveal, drops, drag clamping and keyboard moves use it. `NoteCard` fills its node.
- Properties: `properties/PropertiesPanel.tsx` (board summary, or `notes/NoteFields.tsx` for one note). `NoteFields` (Title = first line, Body = rest, via `notes/titleBody.ts`; counter; read-only colour; author from `RoomView.people`; Delete) is shared with the phone `NoteEditor` sheet. From `md` up, opening a note's editor (double-click, Enter, new note) focuses Title in Properties via `uiStore.requestEdit`; the sheet is phone-only.
- Note nodes always have `style.pointerEvents: "all"`: React Flow drops pointer events on nodes that are neither draggable nor selectable, which broke editing under Hand.
- The canvas keeps the same board point at its centre when its size changes (`geometry.keepCentre`, applied in `BoardCanvas`).

## Multi-select and protocol v7 (slice 2.8)
- `PROTOCOL_VERSION = 7`. Client adds `noteBatch { ops, final }`: a strict envelope with 1 to `MAX_BATCH_ENTRIES` (50) entries, each checked on its own by `checkBatch` (shared): `{ op: "move", id, x, y }`, `{ op: "resize", id, x, y, w, h }`, `{ op: "delete", id }` (strict). A batch naming a note twice is refused whole. Server adds `notesBatchApplied { results, final }` (results shaped exactly like `noteMoved`/`noteResized`/`noteDeleted`); `error` may carry `entries` (refused indexes) and `noteIds` (their notes) so the sender rolls back only those. v6 pages get `version_mismatch`. No stored-schema change.
- Worker (`room.ts` `handleBatch`): invalid entries reported, valid ones applied, unknown/deleted ids ignored. Final: clamped per note, one rev bump per changed note, `NoteStore.applyBatch` in one `transactionSync` (`transactions` counter for tests), one broadcast to everyone. Live (`final: false`): relayed to the others only, coalesced per note in `pendingMoves` (flag `batch`), sent as `notesBatchApplied` per sender, never stored; deletes are ignored in live batches. A batch is one message for `SOCKET_LIMITS`; its entries also spend `BATCH_LIMITS` (600/s, burst 1000), over-budget = `rate_limited` with `noteIds` + a violation (`overLimit`).
- Web session: `startGroupDrag`, `moveGroup` (live: first 50 notes every `GROUP_MOVE_INTERVAL_MS` 100; drop: final chunks of 50, not atomic across chunks), `applyRects` (arrange: moves, or resizes when the size changes), `deleteNotes`; `notesBatchApplied` is folded in one view update; refused `noteIds` roll back last first.
- Pointer model (`canvas/pointer.ts`, by pointer type, never screen size): mouse left on empty canvas = marquee (`canvas/useMarquee.ts`: capture-phase pointerdown with preventDefault so React Flow's d3 pan never starts; `handledClick` stops the pane click double-handling), mouse middle/right = pan, touch/pen = pan, Hand/Space = pan. The canvas suppresses the context menu. Multi-select is md and up only (`BoardCanvas multiSelect`); phones keep one note.
- Selection (`canvas/selection.ts`): insertion-ordered set (first selected = Match size reference), `marqueeSelection` (partial overlap), `selectAll`, `orderedIds`; `uiStore` adds `toggle`, `setSelection`, `selectAll`. `NoteCard`: focus from a press doesn't select (the click or drag decides; keyboard focus still does), Shift/Ctrl/Cmd-click toggles, arrows/Delete act on the whole selection, Alt+arrows only for one. Group drag (`nodes.ts` `createDragHandlers` with `groupFor`/`rectOf`/`startGroupDrag`/`moveGroup`): React Flow drags the grabbed note; the others follow at the offset clamped once for the group (`arrange.groupOffset`). Resize handles show only for a single selection.
- Arrange: pure `canvas/arrange.ts` (`align`, `distribute` (3+, idempotent when the notes don't overlap), `matchSize` (first selected as reference), `groupOffset`, `applyRects`), each returning only changed rects, clamped. `canvas/SelectionBar.tsx` (`FloatingBar` generic, Chalkline's ArrangeBar) sits first in the top stack in `RoomBoard`; since v0.12 it's the permanent `BoardBar` (see below).
- Properties for several: "N selected", `Delete N notes` (confirm), and the Colour/Title text/Body text/Size sections read-only with `mixed` fields ("Mixed", `aria-pressed="mixed"`, no swatch pressed). Editing colour or style for several notes at once needs batch style entries (a later protocol change).

## Delete polish (v0.10.1)
- Web only. `canvas/deleteKey.ts` (pure) decides what a Delete/Backspace reaching the window does: the selected frame, the selected notes (focus on the page, inside the board section, or on an element round it, `onBoard`: a click on the canvas focuses the app's `<main>`, and happy-dom doesn't, so UI tests focus `<main>` themselves; never in fields, modals, with modifiers, from controls elsewhere, or on phones), or nothing. A focused note's own Delete goes through `NoteActions.deleteFromKey`: a note outside the selection deletes the selection. `BoardCanvas` `deleteSelected` is the one path (one note: `confirmDelete`; several: `confirmDeleteNotes(count)`, always asked; not live: no confirm, `deleteNotes` reports offline).
- `RoomSession.deleteNotes` tracks a `DeleteRun` (server ids and unconfirmed clientRefs still to hear about, refused count); when nothing is left it sets `RoomView.deleteReport` (`deleteReportFor`), also on a lost connection. Refusals that only touch the run go in the report, not `noteNotice`. Any update that clears `noteNotice` clears the report. `Notices` shows it as a status.

## Selection fixes (v0.10.2)
- Web only. The frame title `<input>` has `pointer-events-none` until it has focus (`titleFocused` in `frames/FrameNode.tsx`): a click on the header, title included, selects the frame and drags with it, so Delete reaches the window. Double-click the header, Enter on the selected frame (BoardCanvas key handler, `requestFrameEdit`), Tab, or a `frameEditRequest` (new frame) edits it; Enter/Escape commit and blur with the frame still selected.
- Selection look: `.sy-selected` (an outline, not a ring, so it shows with the inline-edit `ring-focus`) on selected notes and frames; with 2+ notes a `.sy-select-badge` check on each (`NoteNode`, `data-select-badge`, `aria-hidden`; selection isn't by colour alone) and a dashed `.sy-selection-box` round them (`BoardCanvas`, `ViewportPortal`, `notesBounds`, `data-selection-box`; follows group drags). Tokens `--sy-select-width/-offset/-badge`, `--sy-selection-pad`; CSS in index.css.

## Arrange grid (v0.10.3)
- Web only, no protocol change. `canvas/arrange.ts` `grid(rects, columns, gap)` (pure): `readingOrder` (row bands by vertical overlap, touching isn't overlap, then x; ties by id), each column as wide as its widest note and each row as tall as its tallest, `GRID_GAP` 24 between cells (mirrored by `--sy-grid-gap`, test checks), anchored at the selection's top-left and shifted back onto the board; sizes unchanged; only moved notes returned; idempotent. Larger than the board = no changes plus a `GridReason` (wide, tall, big). `autoColumns(rects)` picks the count whose estimated grid aspect is closest to the selection's bounding box (log scale, ties to fewer columns, stable on re-run).
- `SelectionBar`: an "Arrange" group (`BarGroup.content` for controls beyond icon commands) with a labelled Grid button and a Columns stepper (1 to the count, Auto = `autoColumns`; `uiStore.gridColumns`, null = auto, session only, not stored, not reset per room). `gridDisabledReason` (`GRID_HINTS`: under 2 notes, not live, a selected note held, one unsaved/local id) shows next to the button. Moves go through `RoomSession.applyRects` (chunking, `BATCH_LIMITS`, per-entry rollback); a grid that doesn't fit shows `GRID_NO_ROOM[reason]` via `RoomSession.showNotice` (cleared by the next note action) and sends nothing. Grid ignored frames until v0.20.0 (frames-only selections now grid; see "Frame multi-select").

## Floating bar and Duplicate (v0.12.0, part 1)
- Web only, no protocol change. From md up `BoardBar` (`canvas/SelectionBar.tsx`) is always there (any tool), toolbar "Board actions", groups History (Undo, Redo), Edit (Duplicate, Delete), Order (front, back; notes only), Arrange (Align, Distribute, Grid + Columns, Match size; behaviour unchanged). Commands with `text` show their label from xl up. Never hide a command: turn it off and give the reason. Phones: no bar. Since v0.15.1 it lives in the top bar (see "Board bar in the top bar").
- Duplicate: pure `canvas/duplicate.ts` (`DUPLICATE_OFFSET` 24 = `--sy-duplicate-offset`, test checks; `duplicateNoteInputs` copies every content field, offset clamped once with `groupOffset`, in stacking order; `duplicateFrameInput` copies the frame alone; `duplicateDisabledReason`, `DUPLICATE_HINTS`). `RoomSession.duplicateNotes(ids)` / `duplicateFrame(id)` go through `addItems` (pacing, confirmation by ref, per-item rollback); refused with nothing sent while offline, for unsaved or held items, while `view.adding`, or without room for every copy (`NOTICES.duplicateNoRoom`). The copies become the selection.
- Ctrl/Cmd shortcuts: pure `canvas/shortcuts.ts` `boardShortcut` (md up, not in fields, modals or controls elsewhere; `onBoard`). BoardCanvas calls `onShortcut` and preventDefaults (Ctrl+D's bookmark). Delete in the bar reuses `deleteSelected` / `deleteFrameAsking` (exported from BoardCanvas, the Delete key's path).

## Export (v0.22.0)
- Web only: no protocol or stored-schema change, nothing sent or stored. Properties' board summary (nothing selected, md and up; phones have no Properties) shows `export/ExportSection.tsx` when `PropertiesRoom.exportViewport` is given (RoomBoard: React Flow store `domNode` -> `.react-flow__viewport`). Hosts and guests, locked or not, connected or not. Off with `EXPORT_NOTICES.empty` as `aria-describedby` text on an empty board; busy text "Exporting…" and both buttons off while one runs; one polite `role=status` line `data-export-status` (start, "PNG downloaded" / "Markdown downloaded", or the plain failure text; the error itself is never shown or logged). Files: `exportFileName` = `stickyard-board-YYYY-MM-DD.png|md` (local date), saved with `downloadBlob` (temporary `<a download>`, removed at once, object URL revoked after `REVOKE_DELAY_MS`; never a data URL, never navigated to).
- Markdown: pure `export/markdown.ts` `boardToMarkdown(ExportBoard, date)`; `ExportBoard` holds only ids, rects, note text, frame titles, shape kind/text and `results` (the revealed `ResultRow[]`, else null), so private dots, names, authors, colours and room codes can't get in. Frames in `readingOrder` (arrange.ts), each with its notes by `framedNotes` (the carry's centre rule), a note going to the first frame only; `## Not in a frame`; `## Labels and shapes` (shapes with text, `SHAPE_KIND_NAMES`); `## Results` (sorted rows, Top voted). Notes `- **Title** body (N dots)`. Every room string goes through `cleanText` (lone surrogates to U+FFFD, all line breaks to spaces, C0/C1/DEL and bidi controls stripped, whitespace collapsed) then `escapeInline` (backslash before every Markdown/HTML-active ASCII character, `://`, `www.` and `@` broken, a leading `-`/`+`/`=`/`1.` escaped). Tests: `test/exportMarkdown.test.ts`.
- PNG: `export/png.ts`. `exportBounds(items)` = `notesBounds` over notes, frames and shapes (each has `w`/`h`, so `noteSize` is right for all three) plus `EXPORT_MARGIN` 64 (= `--sy-export-margin`, test checks; two rows of vote badges fit above a top note). `exportSize(w, h)`: scale `EXPORT_SCALE` 2, lowered so neither side passes 8,192 px and the total stays under 16 MP (iOS). `renderPng(viewport, bounds, load)`: `getViewportForBounds(bounds, w, h, 1, 1, 0)` (100% zoom), `html-to-image` `toBlob` (1.11.13, pinned, dynamic import: its own chunk) with `pixelRatio`, the resolved `--sy-board` as background, and `keepInExport` as the filter (leaves out the board's dot-grid node, resize controls, node toolbars, select badges, the selection box, cursors, my dots, and anything with `data-export-skip`, e.g. the frame grip). `.sy-exporting` on the viewport while drawing (index.css: no selection outline or ring, no transitions), removed in `finally`. Tests: `test/exportPng.test.ts`, `test/exportUi.test.tsx`; drawing checked in Chromium (Inter embedded, theme kept).

## Board size, protocol v16 (v0.23.0)
- `BOARD_WIDTH`/`BOARD_HEIGHT` (shared) are 6400 x 4000 (were 3200 x 2000); `PROTOCOL_VERSION = 16`, v15 pages get `version_mismatch`; no stored-schema bump. Every user reads the constants: shared clamps (`clampNotePosition`/`clampNoteRect`, frame and shape clamps, `groupOffset`), schema maxima (`boardX`/`boardY`, item rect checks, cursor tolerance and `clampCursor`), web `geometry.ts` (`panExtent` = board + `PAN_MARGIN`, the empty-board fit at the board's middle), `nodes.ts` (`BOARD_NODE`: the visible edge, minimap shape and drag `extent`), `BoardCanvas` `nodeExtent`, `notes/size.ts` `sizeAt` cap, `templates/place.ts` clamp, `arrange.ts` grid wide/tall and shift-back, `cursors.ts` `onBoardPoint`, `CursorLayer` (its fallback visible area was the only literal copy), Properties "Board size". tokens.css mirrors them (`--sy-board-width/-height`, test checks).
- Unchanged by decision: `MIN_ZOOM` 0.1, `MAX_ZOOM` 2, `FIT_MAX_ZOOM` 1, note, frame and shape size limits. New items still go at the viewport centre (`newNotePosition`, `templateOrigin`, palette drops). At `MIN_ZOOM` the board is 640 px wide, so phones see part of it; React Flow's `translateExtent` also keeps zoom-out from going below the zoom where the pan extent covers the canvas (about 19% at 1280 with both panels). Tests: `shared/test/boardSize.test.ts`, `worker/test/boardSize.test.ts`, `web/test/boardSize.test.ts`.

## Panel layout at 768 px (v0.24.0, part 1)
- Web only. `panels/layout.ts` `storedPanelState(raw, limits)` (null when nothing or something malformed is stored; a well-formed entry with an out-of-range width keeps its collapsed state) and `initialPanelState(raw, limits, desktop)`: the stored choice wins, else open from lg (`MEDIA.desktop`, 1024) and collapsed below it. `parsePanelState` is `storedPanelState ?? DEFAULT_PANEL_STATE`. `panelStore` decides once, when the store is made (before the board's first render, so the first fit measures the final canvas), and never writes the default. Tests: `test/panelDefaults.test.ts` (pure and store, with a `setItem` spy).
- The 16% first fit at 768 was the 360 px canvas between two open panels, not a race (measured: the width was final at the first sample). Now 39% on the shots board.
- Narrow canvas: the view bar wraps (`ToolBars` `Bar` `flex-wrap max-w-full`, `rounded-lg` and `data-wrapped` when wrapped; its wrapper has `px-gutter`). `RoomBoard` `useBox` measures the bar (width for `cornerLifted`, height > 1.5 touch targets = wrapped) and puts `.sy-bar-wrapped` on the canvas column, which redefines `--sy-above-bar` and `--sy-chat-above-bar-minimap` with `--sy-bar-h-wrapped` (tokens.css) so the minimap and chat button sit above two rows.

## Navigation (v0.24.0, part 2)
- Web only, no protocol or stored-schema change. Pure rules in `canvas/navigation.ts` (tested in `test/navigation.test.ts`): `FIT_READABLE_ZOOM` 0.25, `CLUSTER_GAP` 600 (edge-to-edge, larger axis gap; exactly 600 doesn't link), `JUMP_MIN_ZOOM` 0.5, `VIEW_ANIMATION_MS` 200 (= `--sy-duration-base`, test checks) and `viewDuration(reducedMotion)`; `itemGap`, `clusters` (union-find, input order kept), `largestCluster` (most items, then nearest the board centre, then smaller y, then smaller x), `inViewport`, `fitPlan` (`{ viewport, partial, outside }`), `selectionViewport`, `zoomSelectionReason`/`ZOOM_SELECTION_HINT`, `jumpViewport`, `JUMP_HINT`. `geometry.fitZoom` is the unfloored fit zoom `fitViewport` now uses.
- `useCanvasView`: one `go` path for every view change, duration from `viewDuration` (matchMedia `MEDIA.reducedMotion`). `fit` (plain, floor-free: templates and Show all), `fitItems` (Fit to notes and the first fit, returns the plan), `zoomTo` (selection), `jumpTo`, `centreAt` (minimap click).
- `uiStore`: `viewNotice` (`{ kind: "outside" } | { kind: "jump", name }`, each with a counter `n`) and `jumpRequest` (`requestJump(id)`), both cleared by `resetRoom`. `canvas/ViewNotices.tsx` (last in the `Notices` stack): an always-present polite `role=status`; "Some items are out of view." with Show all and Dismiss (stays until one of them or the next view command), or "Moved to <name>’s pointer." (gone after `JUMP_NOTICE_MS` 4 s). `showFitNotice(partial)` is shared by the F/ribbon Fit and the first fit in `BoardCanvas`.
- Tools: `zoom-selection` (view bar only, slot 4.5, shortcut **S**, `Focus` icon, `explain: true`); `ToolContext` gains `zoomSelection` and `selectionReason`. `Tool.explain` renders `ExplainedToolButton`: `aria-disabled` (focusable), a tooltip above (`role=tooltip`, `data-tool-tip`) with the name and shortcut or the reason, shown on hover or focus, Escape hides it; other view-bar tools keep native `disabled` and `title`.
- Minimap: already `pannable`/`zoomable` (drag pans, wheel zooms); `onClick` centres the view at the clicked point (same zoom), unless the press moved past the drag threshold (a capture `pointerdown` on the board section plus a window `pointermove`, `minimapDrag`). The marquee ignores `.react-flow__minimap` (unchanged). Its world is still the whole board (React Flow's bounds include the board node): backlog.
- `RoomBoard` handles `jumpRequest`: reads `useCursors.lastSeen` and the participant, `canvas.jumpTo`, then the jump notice with `truncateName` (16). See connection.md "Navigation: last known pointers". UI tests: `test/navigationUi.test.tsx`.

## Follow: programmatic moves versus mine (v0.31.0)
- `useCanvasView({ onUserMove })`: my own view commands call `onUserMove` (following stops); `follow` and `showView` are programmatic (inside `MoveGuard`); `moved(event)` from React Flow `onMove` and `userGesture()` from the overview map. `fitItems(items, animate, user)`: the first fit passes `user` false. `view()` is my view on the wire (`viewFromCentre`). Details in connection.md "Follow and Bring to me: the UI".
