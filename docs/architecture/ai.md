# AI: Settings, your own key, the client

Architecture notes for slice 10 AI. Sections are in build order and keep the version that introduced them; later sections can override earlier ones. A quoted section name may live in another file: see `docs/architecture/README.md`.

## Settings and bring your own key (v0.42.0, 10a, AI part 1 of 4)

- Decision (15 October 2026): bring your own Anthropic key, as Chalkline does. The page calls api.anthropic.com directly with plain fetch (no SDK, no proxy, no Worker). There is no server-side secret; whoever presses an AI button pays with their own key. Web only: no protocol, relay or stored-schema change (protocol 23, schema 14). Nothing AI-related may ever go over the WebSocket or into a message schema.
- No AI feature exists yet. The only call to Anthropic is Test key. Parts 10b (board setup from a prompt), 10c (summary and sentiment) and 10d (iterative edits) reuse what is here.

### Behaviour
- Settings is a menu item in the last group (before About) on every screen, with or without a room. Store-driven like Share session (not a hash route), so it stacks over any sheet: focus starts on Close, Esc closes it alone, focus returns to the menu button (the stacked `trapFocus`). Confirmation steps are pages inside the sheet; closing a page returns focus to what opened it (Test key, or the Remember radio).
- AI section, top to bottom: the intro; the status line (`statusText`: "No key saved." / "Key saved for this session only (•••• abcd). It's forgotten when you reload or close the tab." / "Key remembered on this device (•••• abcd).") with "Last test worked/failed at HH:MM."; the key form (no key, or Replace key) or Test key / Replace key / Remove key; the error box; Keep the key (two radios).
- The key form: label "Anthropic API key", password input, monospace, autocomplete, autocapitalize and autocorrect off, spellcheck false, `data-1p-ignore`, `data-lpignore`, Show/Hide (`aria-pressed`), a hint linking the Claude Console's API keys page, Save key, Cancel when replacing. The field is cleared as soon as the key is saved (the typed draft is the only place the page holds it outside keyStore). An empty field says "Paste your key first."
- Remove key: no confirm, both places cleared, announced. Changing the Keep the key choice moves a saved key; choosing Remember goes through the warning page first (red border and text, Cancel focused). Blocked storage falls back to this session only and says so.
- Test key: the check page first, then two count_tokens calls; "Testing the key…" with Cancel while it runs. A key change (save, replace, remove) aborts a running test and drops its result (`keyVersion`). Success: "Last test worked at HH:MM." in the status box and announced. Failure: the error box (`role=alert`) names the failed model(s), the table's title, message and next step, Details (redacted) and Retry (always offered for Test key: counting is free; Retry runs the test again without the check page).

### The client
- Streaming: SSE parsed by blank-line blocks (CRLF tolerated, a `\r` split across chunks held back), `data:` lines JSON-parsed as untrusted data. `message_start` (usage), `content_block_delta` `text_delta` (accumulated; `onProgress(characters so far)`), `message_delta` (stop_reason, cumulative usage), `message_stop`; `ping` and unknown events ignored; an `error` event maps by its type. A stream that ends without `message_stop` is `malformed` and keeps the text so far; `stop_reason` `max_tokens` is `truncated`, `refusal` is `refused`.
- Timeout (`DEFAULT_IDLE_TIMEOUT_MS` 60 s, Test key 20 s): time without data, restarted by the response headers and every chunk; never total time. Cancel through an AbortSignal; an already-aborted signal never calls fetch. No automatic retries anywhere.
- Status mapping: 401 invalid key; 403 permission; 402 billing; 400 with "credit balance" in the message billing (Anthropic reports an empty credit balance as a 400 invalid_request_error; the errors page doesn't spell out that message, the wording is from reports of it); 400 with "spend" or "usage limit" spend limit (the errors page: a spend limit you set is a 400); other 400 bad request; 404 `not_found_error` whose message is about the model (`model: <id>`) model unavailable, any other 404 bad request; 413 too large; 429 rate limited with retry-after (seconds or an HTTP date), or spend limit when the message is about a spend cap and there's no retry-after; 529 or `overloaded_error` overloaded; other 5xx server. A fetch that throws: offline when `navigator.onLine` is false, else blocked (a guess: CORS, ad blockers and DNS look the same). The request id comes from the `request-id` header, else the body's `request_id`.

### Leaks and storage
- The key never reaches: the WebSocket (join included), the URL, the board file, a stencil or the stencils storage, the preferences, an error's Details, the DOM after saving, or the console. Nothing under `src/ai` calls `console`. Tests: `web/test/aiLeak.test.tsx` (a real room page with a remembered key and a session key, the real Export board file, a saved stencil, every storage value, console spies; a registry test that every stored key is owned).
- `STORAGE_KEYS.aiKey` (`stickyard:ai-key`) is listed in `SECRET_STORAGE_KEYS` (`isSecretStorageKey`): anything that ever lists, backs up or exports stored values must skip it. `STORAGE_KEYS.aiPrefs` (`stickyard:ai-prefs`) never holds the key.
- No Content-Security-Policy exists (checked 15 October 2026: none in `web/index.html`, the Vite config or the Pages workflow), so none was added; the backlog has "add a CSP (connect-src for the Worker, wss and api.anthropic.com)". `index.html` already sends `referrer: no-referrer`.
